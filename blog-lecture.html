6 Article 엔티티 (@Entity)

🎯 학습목표
  • @Entity로 클래스를 테이블과 매핑하고, 생성·수정 시각을 자동으로 기록할 수 있다.
  • 빌더 패턴과 의미 있는 변경 메서드(update())로 객체를 다룬다.

📖 개념 및 설명

  • @NoArgsConstructor(access = PROTECTED) — JPA가 쓰는 기본 생성자를 만들되, 외부에서 함부로 new Article() 하지 못하게 막는다.
  • @Builder — Article.builder().title(..).content(..).build() 형태로 읽기 쉽게 생성한다.
  • @CreatedDate / @LastModifiedDate + AuditingEntityListener — 저장·수정 시각 자동 기록 (메인 클래스의 @EnableJpaAuditing 필요)
  • Setter 대신 update() 메서드로만 값을 바꾼다 → 변경 지점이 한곳에 모인다.
💡 domain/Article.java
package com.sudo.blog.domain;

@EntityListeners(AuditingEntityListener.class)
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
@Entity
public class Article {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)   // PK 자동 증가
    @Column(name = "id", updatable = false)
    private Long id;

    @Column(name = "title", nullable = false)
    private String title;

    @Column(name = "content", nullable = false)
    private String content;

    @Column(name = "image_url")
    private String imageUrl;          // 업로드한 이미지 경로 (/uploads/xxx.jpg)

    @CreatedDate
    @Column(name = "created_at")
    private LocalDateTime createdAt;

    @LastModifiedDate
    @Column(name = "updated_at")
    private LocalDateTime updatedAt;

    @Builder   // 빌더 패턴으로 객체 생성
    public Article(String title, String content, String imageUrl) {
        this.title = title;
        this.content = content;
        this.imageUrl = imageUrl;
    }

    // 요청 받은 값으로 수정 (트랜잭션 안에서 호출 → 자동 UPDATE)
    public void update(String title, String content, String imageUrl) {
        this.title = title;
        this.content = content;
        this.imageUrl = imageUrl;
    }
}

8 DTO (요청 · 응답 데이터)

🎯 학습목표
  • 엔티티를 그대로 노출하지 않고 용도별 DTO로 나누는 이유를 설명할 수 있다.

📖 개념 및 설명

클라이언트가 보낸 JSON은 요청 DTO로 받고, 화면·API에 필요한 값만 응답 DTO에 담아 돌려준다. 엔티티가 바뀌어도 API 형식이 흔들리지 않는다.

DTO용도필드
AddArticleRequest글 등록 요청title, content, imageUrl + toEntity()
UpdateArticleRequest글 수정 요청title, content, imageUrl
ArticleResponseAPI 응답title, content, imageUrl
ArticleListViewResponse목록 화면id, title, content, imageUrl
ArticleViewResponse상세·수정 화면id, title, content, imageUrl, createdAt
UploadResponse (record)업로드 결과imageUrl
WritingSuggestionRequest/Response (record)AI 도우미title, content, question / suggestions
AddUserRequest회원가입 폼email, password
💡 dto/AddArticleRequest.java — DTO → 엔티티 변환
@NoArgsConstructor
@AllArgsConstructor
@Getter
public class AddArticleRequest {
    private String title;
    private String content;
    private String imageUrl;

    // DTO를 엔티티로 만들어 주는 메서드
    public Article toEntity() {
        return Article.builder()
                .title(title)
                .content(content)
                .imageUrl(imageUrl)
                .build();
    }
}
💡 dto/ArticleResponse.java · UploadResponse.java
@Getter
public class ArticleResponse {
    private final String title;
    private final String content;
    private final String imageUrl;

    public ArticleResponse(Article article) {   // 엔티티 → 응답 DTO
        this.title = article.getTitle();
        this.content = article.getContent();
        this.imageUrl = article.getImageUrl();
    }
}

// record — 필드·생성자·getter 자동 생성
public record UploadResponse(String imageUrl) {}

9 BlogService (업무 로직)

🎯 학습목표
  • 업무 로직을 Service에 모으고, @Transactional과 더티 체킹으로 수정을 처리한다.

📖 개념 및 설명

  • @RequiredArgsConstructor — final 필드를 받는 생성자를 Lombok이 만들어 생성자 주입이 된다.
  • 더티 체킹(dirty checking) — 트랜잭션 안에서 조회한 엔티티의 값을 바꾸면, 끝날 때 JPA가 변경을 감지해 UPDATE를 자동 실행한다. save()를 다시 부를 필요가 없다.
  • 없는 id를 조회하면 IllegalArgumentException("not found: id")를 던진다.
💡 service/BlogService.java
@RequiredArgsConstructor   // final 필드 생성자 주입
@Service
public class BlogService {
    private final BlogRepository blogRepository;

    // 글 추가
    public Article save(AddArticleRequest request) {
        return blogRepository.save(request.toEntity());
    }

    // 전체 글 조회
    public List<Article> findAll() {
        return blogRepository.findAll();
    }

    // 글 1건 조회
    public Article findById(long id) {
        return blogRepository.findById(id)
                .orElseThrow(() -> new IllegalArgumentException("not found: " + id));
    }

    // 글 삭제
    public void delete(long id) {
        blogRepository.deleteById(id);
    }

    // 글 수정 — 트랜잭션 종료 시 변경 내용 자동 반영
    @Transactional
    public Article update(long id, UpdateArticleRequest request) {
        Article article = blogRepository.findById(id)
                .orElseThrow(() -> new IllegalArgumentException("not found: " + id));
        article.update(request.getTitle(), request.getContent(), request.getImageUrl());
        return article;
    }
}

10 BlogApiController (REST)

🎯 학습목표
  • HTTP 메서드별 매핑 애너테이션과 ResponseEntity로 상태코드를 지정해 응답할 수 있다.

📖 개념 및 설명

  • @RestController = @Controller + @ResponseBody → 반환 객체를 JSON으로 변환한다.
  • @RequestBody는 JSON 본문을 DTO로, @PathVariable은 URL의 {id}를 변수로 받는다.
  • ResponseEntity.status(HttpStatus.CREATED)로 등록 성공 시 201을 돌려준다.
💡 controller/BlogApiController.java
@RequiredArgsConstructor
@RestController   // 객체를 JSON으로 반환
public class BlogApiController {
    private final BlogService blogService;
    private final WritingAssistantService writingAssistantService;

    // 글 등록 → POST /api/articles
    @PostMapping("/api/articles")
    public ResponseEntity<Article> addArticle(@RequestBody AddArticleRequest request) {
        Article savedArticle = blogService.save(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(savedArticle);
    }

    // 글 목록 → GET /api/articles
    @GetMapping("/api/articles")
    public ResponseEntity<List<ArticleResponse>> findAllArticles() {
        List<ArticleResponse> articles = blogService.findAll()
                .stream()
                .map(ArticleResponse::new)
                .toList();
        return ResponseEntity.ok().body(articles);
    }

    // 글 조회 → GET /api/articles/1
    @GetMapping("/api/articles/{id}")
    public ResponseEntity<ArticleResponse> findArticle(@PathVariable long id) {
        return ResponseEntity.ok().body(new ArticleResponse(blogService.findById(id)));
    }

    // 글 삭제 → DELETE /api/articles/1
    @DeleteMapping("/api/articles/{id}")
    public ResponseEntity<Void> deleteArticle(@PathVariable long id) {
        blogService.delete(id);
        return ResponseEntity.ok().build();
    }

    // 글 수정 → PUT /api/articles/1
    @PutMapping("/api/articles/{id}")
    public ResponseEntity<Article> updateArticle(@PathVariable Long id,
                                                 @RequestBody UpdateArticleRequest request) {
        return ResponseEntity.ok().body(blogService.update(id, request));
    }

    // AI 글쓰기 제안 → POST /api/ai-suggestions
    @PostMapping("/api/ai-suggestions")
    public ResponseEntity<WritingSuggestionResponse> writingAssist(
            @RequestBody WritingSuggestionRequest request) {
        return ResponseEntity.ok().body(writingAssistantService.getWritingAssist(request));
    }
}

11 Thymeleaf 화면 구성

🎯 학습목표
  • @Controller에서 Model에 데이터를 담아 템플릿으로 넘길 수 있다.
  • th:text · th:each · th:if · @{...} 문법을 사용할 수 있다.

📖 자주 쓰는 Thymeleaf 문법 (example.html로 연습)

문법의미예
${...}모델 값 꺼내기th:text="${article.title}"
*{...}th:object로 선택한 객체의 필드th:text="*{name}"
@{...}URL 만들기@{/articles/{id}(id=${item.id})}
th:each반복th:each="item : ${articles}"
th:if조건부 출력th:if="${article.id} == null"
|...|문자열 합치기th:text="|Posted on ${...}|"
#temporals날짜 포맷${#temporals.format(today, 'yyyy-MM-dd')}

💡 service/FileStorageService.java · LocalFileStroageService.java
public interface FileStorageService {
    UploadResponse store(byte[] bytes, String filename);
}

@Service
public class LocalFileStroageService implements FileStorageService {
    private final Path uploadDir;

    // app.upload-dir 설정이 없으면 기본값 "uploads"
    public LocalFileStroageService(@Value("${app.upload-dir:uploads}") String uploadDir) {
        this.uploadDir = Paths.get(uploadDir).toAbsolutePath().normalize();
    }

    @Override
    public UploadResponse store(byte[] bytes, String filename) {
        try {
            Files.createDirectories(uploadDir);
            String ext = filename.contains(".")
                    ? filename.substring(filename.lastIndexOf('.'))
                    : ".png";
            String saved = UUID.randomUUID() + ext;          // 고유한 파일명
            Files.write(uploadDir.resolve(saved), bytes);
            return new UploadResponse("/uploads/" + saved);
        } catch (IOException e) {
            throw new RuntimeException("파일 저장에 실패했습니다.", e);
        }
    }
}

14 Spring AI — AI 글쓰기 도우미

🎯 학습목표
  • 프롬프트 템플릿(.st)에 값을 채워 LLM에 보낼 수 있다.
  • BeanOutputConverter로 LLM의 답을 자바 객체로 받을 수 있다.

📖 동작 원리

모달에서 질문 입력→POST /api/ai-suggestions→템플릿에 제목·내용·질문·{format} 채움→ChatClient → Gemini→JSON → WritingSuggestionResponse→제안 클릭 시 본문에 추가
  • {format} 자리에는 BeanOutputConverter.getFormat()이 만든 "이 JSON 스키마로 답하라"는 지시문이 들어간다.
  • 그래서 LLM의 답을 {"suggestions": ["...", "...", "..."]} 형태로 받아 record로 바로 변환할 수 있다.
💡 resources/prompts/writing-assistant.st
당신은 블로그 글쓰기를 도와주는 전문 작가입니다.

제목: {title}
현재 작성된 내용: {content}
질문: {question}

위 질문에 대해 3개의 구체적이고 실용적인 제안을 해 주세요.

{format}
💡 dto (record) · service/WritingAssistantService.java
public record WritingSuggestionRequest(String title, String content, String question) {
    public Map<String, Object> toMap(String format) {
        return Map.of("title", title, "content", content,
                      "question", question, "format", format);
    }
}

public record WritingSuggestionResponse(List<String> suggestions) {}

@Service
public class WritingAssistantService {
    private final ChatClient chatClient;
    private final PromptTemplate template;

    // LLM의 JSON 응답 → WritingSuggestionResponse 변환기
    private final BeanOutputConverter<WritingSuggestionResponse> outputConverter =
            new BeanOutputConverter<>(WritingSuggestionResponse.class);

    public WritingAssistantService(
            ChatClient.Builder chatClientBuilder,
            @Value("classpath:prompts/writing-assistant.st") Resource promptResource) {
        this.chatClient = chatClientBuilder.build();
        this.template = new PromptTemplate(promptResource);
    }

    public WritingSuggestionResponse getWritingAssist(WritingSuggestionRequest request) {
        // 1) 템플릿에 값 채워 최종 프롬프트 생성
        String prompt = template.create(request.toMap(outputConverter.getFormat())).getContents();
        // 2) LLM 호출
        String response = chatClient.prompt().user(prompt).call().content();
        // 3) JSON → 객체
        return outputConverter.convert(response);
    }
}

16 JWT 토큰 (TokenProvider)

🎯 학습목표
  • JWT의 구조(헤더·페이로드·서명)와 발급·검증 과정을 이해한다.

📖 개념 및 설명

  • 세션 방식: 서버가 로그인 상태를 기억한다. JWT 방식: 서버가 서명한 토큰을 클라이언트가 들고 다니며 매 요청 Authorization: Bearer 토큰으로 보낸다.
  • 토큰 = 헤더.페이로드.서명. 페이로드에 발급자(iss)·발급일(iat)·만료일(exp)·사용자(sub)·id를 담고, 비밀키로 서명해 위조를 막는다.
  • 현재 프로젝트는 토큰 발급·검증 클래스까지 만든 상태다. 요청마다 토큰을 검사하는 필터는 실습 3에서 완성한다.
💡 config/jwt/JwtProperties.java · TokenProvider.java
@Setter
@Getter
@Component
@ConfigurationProperties("jwt")   // application.yaml의 jwt.issuer, jwt.secret_key
public class JwtProperties {
    private String issuer;
    private String secretKey;
}

@RequiredArgsConstructor
@Service
public class TokenProvider {
    private final JwtProperties jwtProperties;

    // 토큰 발급
    public String generateToken(User user, Duration expiredAt) {
        Date now = new Date();
        return Jwts.builder()
                .setHeaderParam(Header.TYPE, Header.JWT_TYPE)
                .setIssuer(jwtProperties.getIssuer())
                .setIssuedAt(now)
                .setExpiration(new Date(now.getTime() + expiredAt.toMillis()))
                .setSubject(user.getEmail())
                .claim("id", user.getId())
                .signWith(SignatureAlgorithm.HS256, jwtProperties.getSecretKey())
                .compact();
    }

    // 유효성 검증 (서명·만료)
    public boolean validToken(String token) {
        try {
            Jwts.parser().setSigningKey(jwtProperties.getSecretKey()).parseClaimsJws(token);
            return true;
        } catch (Exception e) {
            return false;
        }
    }

    // 토큰 → 인증 정보
    public Authentication getAuthentication(String token) {
        Claims claims = getClaims(token);
        Set<SimpleGrantedAuthority> authorities =
                Collections.singleton(new SimpleGrantedAuthority("ROLE_USER"));
        return new UsernamePasswordAuthenticationToken(
                new org.springframework.security.core.userdetails.User(
                        claims.getSubject(), "", authorities), token, authorities);
    }

    public Long getUserId(String token) {
        return getClaims(token).get("id", Long.class);
    }

    private Claims getClaims(String token) {
        return Jwts.parser().setSigningKey(jwtProperties.getSecretKey())
                .parseClaimsJws(token).getBody();
    }
}

실습 1. 전역 예외 처리 (@RestControllerAdvice)

없는 글을 조회·수정할 때 500 대신 404 Not Found와 {"error":"not found: 999"}를 돌려주도록 GlobalExceptionHandler를 만드세요.

힌트 보기
@RestControllerAdvice   // 모든 컨트롤러의 예외를 여기서 처리
public class GlobalExceptionHandler {

    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<Map<String, String>> handleNotFound(IllegalArgumentException e) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
                .body(Map.of("error", e.getMessage()));
    }
}

실습 3. JWT 인증 필터 완성 ★

OncePerRequestFilter를 상속한 TokenAuthenticationFilter를 만들어, 요청 헤더 Authorization: Bearer 토큰을 검사하고 유효하면 SecurityContext에 인증 정보를 넣으세요. 로그인 성공 시 토큰을 발급하는 POST /api/token도 추가합니다.

힌트 보기
@RequiredArgsConstructor
public class TokenAuthenticationFilter extends OncePerRequestFilter {
    private final TokenProvider tokenProvider;

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);
            if (tokenProvider.validToken(token)) {
                SecurityContextHolder.getContext()
                        .setAuthentication(tokenProvider.getAuthentication(token));
            }
        }
        filterChain.doFilter(request, response);
    }
}

실습 4. 목록 페이징 & 최신순 정렬

글이 많아지면 한 번에 다 보여줄 수 없다. Pageable로 한 페이지에 5개씩, 최신 글이 먼저 오도록 바꾸고 목록 화면 아래에 페이지 번호를 만드세요.

// 서비스
public Page<Article> findPage(int page) {
    return blogRepository.findAll(PageRequest.of(page, 5, Sort.by("id").descending()));
}

// 뷰 컨트롤러 — /articles?page=0
@GetMapping("/articles")
public String getArticles(@RequestParam(defaultValue = "0") int page, Model model) {
    Page<Article> result = blogService.findPage(page);
    model.addAttribute("articles", result.map(ArticleListViewResponse::new).getContent());
    model.addAttribute("totalPages", result.getTotalPages());
    return "articleList";
}
