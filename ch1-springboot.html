1 스프링 부트(Spring Boot)란?

🎯 학습목표
  • 스프링 부트가 무엇이고 스프링 프레임워크와 어떤 관계인지 설명할 수 있다.
  • 스프링 부트의 4가지 특징(스타터 · 자동 설정 · 내장 서버 · 실행 가능한 JAR)을 말할 수 있다.

📖 스프링 부트(Spring Boot)란?

스프링 프레임워크의 서브 프로젝트로, 이름처럼 스프링 + 부트의 합성어다. 부트(Boot)는 “컴퓨터를 부팅한다”는 말처럼 시스템을 바로 사용 가능한 상태로 만든다는 뜻이며, 웹 애플리케이션을 빠르게 만들어 출시할 수 있는 경량 오픈소스 프레임워크다. 2014년 무렵 출시되어 지금은 스프링 개발의 사실상 표준이 되었다.

📖 스프링 부트의 특징

특징설명
① 라이브러리 관리 자동화Maven · Gradle로 하나씩 관리하던 의존성을 스타터(Starter) 하나로 묶어 간단히 추가한다. 예) spring-boot-starter-webmvc 하나로 웹 개발에 필요한 라이브러리가 모두 들어온다.
② 설정의 자동화추가된 라이브러리를 보고 실행에 필요한 스프링 설정을 자동으로 해 준다. (Auto Configuration)
③ 테스트 환경과 내장 서버JUnit 등 테스트 라이브러리가 기본 포함되고, 톰캣(Tomcat)을 내장하고 있어 main() 메서드만 실행하면 서버가 뜬다.
④ 독립 실행 가능한 JARWAR 대신 JAR로 패키징해 java -jar 파일.jar 한 줄로 운영 서버에서 실행할 수 있다.

2 개발 환경 구축 — JDK · IntelliJ

🎯 학습목표
  • JDK 21을 설치하고 JAVA_HOME 환경 변수를 설정할 수 있다.
  • IntelliJ IDEA를 설치하고 Lombok · 자동 빌드 설정을 할 수 있다.

2-1. JDK 21 설치

📖 오라클 Java 다운로드

검색: 오라클 java 다운로드 → JDK 21 탭 → Windows → x64 Installer(.exe) 다운로드 후 설치한다. 기본 설치 경로는 C:\Program Files\Java\jdk-21이다.

💡 IntelliJ에서 JDK 받기 IntelliJ에서도 JDK를 바로 받을 수 있다: File → Project Structure → SDK → Add SDK → Download JDK → Version 21 · Vendor(Oracle OpenJDK / Eclipse Temurin 등) 선택.

2-2. 환경 변수 설정

순서설정
1시스템 속성 → 환경 변수 → 시스템 변수 → 새로 만들기
변수 이름: JAVA_HOME · 변수 값: C:\Program Files\Java\jdk-21
2시스템 변수 → Path → 편집 → 새로 만들기 → %JAVA_HOME%\bin 추가
3명령 프롬프트(cmd)를 새로 열고 java -version으로 확인
⚠️ JAVA_HOME 주의 JAVA_HOME 값은 bin을 뺀 JDK 폴더(...\jdk-21)여야 한다. PPT 캡처처럼 ...\jdk-21\bin으로 넣으면 Path의 %JAVA_HOME%\bin이 ...\bin\bin이 되어 java를 찾지 못한다.
💡 명령 프롬프트 — 설치 확인
java -version
javac -version
echo %JAVA_HOME%

2-3. IntelliJ IDEA 설치

📖 IntelliJ IDEA 설치

jetbrains.com/idea → Download → Windows(.exe) 설치. 설치 옵션에서 Create Desktop Shortcut, Add “Open Folder as Project”, .java 연결을 체크하면 편하다. 이클립스/STS와 달리 HTML · CSS · JS 편집 기능이 기본 포함되어 있어 별도 플러그인(Web Developer Tools)이 필요 없다.

📌 마법사가 안 보이면 Spring Boot 프로젝트 생성 마법사(New Project → Spring Boot)는 Ultimate(유료 · 학생 무료) 기능이다. 마법사가 없으면 start.spring.io에서 같은 설정으로 프로젝트를 만들어 ZIP을 풀고 File → Open으로 열면 된다.

3 jwboot 프로젝트 만들기 · 실행

🎯 학습목표

  • 프로젝트 폴더 구조(java · static · templates · 설정 파일)를 설명할 수 있다.
  • 애플리케이션을 실행하고 localhost:8080에 접속할 수 있다.

3-2. build.gradle

plugins {

📌 참고 Maven의 pom.xml 역할을 Gradle에서는 build.gradle이 한다. 의존성을 고치면 오른쪽 위 🐘 Load Gradle Changes를 눌러 내려받는다. Spring Boot 4 생성기는 Spring Web을 spring-boot-starter-webmvc로 넣는다(3.x의 starter-web과 같은 역할).

💡 JwbootApplication.java — 메인 클래스

4 static — 정적 파일

🎯 학습목표
  • static 폴더의 정적 파일(html · 이미지)을 주소로 바로 열 수 있다.

📖 static — 정적 파일

static 폴더에 넣은 파일은 컨트롤러 없이 파일 경로 그대로 접근된다. static/hello.html → localhost:8080/hello.html, static/images/time.jpg → localhost:8080/images/time.jpg

💡 static/hello.html
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>hello~</title>
</head>
<body>
    <h2>Hello~ 스프링부트!</h2>
</body>
</html>
📁 이미지 넣기 static 아래에 images 폴더를 만들고 time.jpg(모래시계 사진)를 넣는다. IntelliJ에서는 탐색기의 이미지 파일을 프로젝트 창의 폴더로 드래그하면 복사된다.

5 메인 페이지 만들기 — 컨트롤러 · 템플릿 · 정적 파일

🎯 학습목표
  • @Controller와 @GetMapping으로 URL을 템플릿(html)에 연결할 수 있다.
  • templates의 html에서 static의 css · js · 이미지를 사용할 수 있다.

📖 완성 화면

/에서 홈 화면, 시간 페이지로 이동을 누르면 /time에서 모래시계 사진과 1초마다 바뀌는 현재 시각이 나온다.

5-1. URL 매핑 — HomeController

💡 controller/HomeController.java
package com.springboot.controller;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;

@Controller
public class HomeController {

    @GetMapping("/")
    public String home() {
        return "home";          // templates/home.html
    }

    @GetMapping("/time")
    public String time() {
        return "pages/time";    // templates/pages/time.html
    }
}
⚠️ 뷰 이름 앞 슬래시 PPT는 return "/pages/time";처럼 앞에 /를 붙였다. IntelliJ 실행에서는 동작하지만 JAR로 패키징해 실행하면 템플릿을 못 찾는 경우가 있으므로 "pages/time"처럼 슬래시 없이 쓴다.

6 스프링 MVC — 계층 구조와 요청 매핑

🎯 학습목표
  • 스프링 MVC의 3계층 구조(Controller · Service · Repository)를 설명할 수 있다.
  • @RequestMapping · @GetMapping · @RestController의 차이를 이해하고 사용할 수 있다.

6-1. 계층 구조

브라우저 요청→Controller
MemberController.java→Service
MemberService.java→Repository
MemberRepository.java→DB
계층구성 요소 (예)어노테이션역할
프레젠테이션 계층컨트롤러 MemberController.java · 뷰 members.html@Controller클라이언트 요청 처리, 화면 반환
비즈니스 계층MemberService.java@Service비즈니스 로직 수행
퍼시스턴스 계층MemberRepository.java@Repository데이터베이스 접근 · CRUD 처리
모델 (도메인 객체)Member.java(엔티티 · DTO)계층 사이에 주고받는 데이터

📖 컨트롤러(@Controller)

스프링 부트가 웹 요청을 받으면 먼저 내장 톰캣의 디스패처 서블릿(DispatcherServlet)으로 전달한다. 디스패처 서블릿은 요청을 받는 창구 역할만 하고 실제 처리는 컨트롤러가 한다.

@Controller는 사용자의 요청을 받아 처리(서비스 계층에 위임)하고, 결과를 뷰 리졸버(View Resolver)를 통해 찾은 HTML(템플릿)로 응답하는 클래스에 붙인다.

요청→DispatcherServlet→@Controller→뷰 이름 반환 "home"→View Resolver→templates/home.html

📖 리포지터리(@Repository)

데이터 접근 계층(DAO · Repository), 즉 DB와 직접 통신하는 클래스임을 스프링에게 알리는 어노테이션이다. @Repository(그리고 @Controller, @Service)가 붙은 클래스는 스프링이 자동으로 찾아 빈(Bean)으로 등록하므로, 생성자 주입이나 @Autowired로 바로 가져다 쓸 수 있다.

6-2. @RequestMapping — 요청 경로 매핑

형식설명
@RequestMapping(value="URL", method=RequestMethod.GET)URL과 HTTP 메서드를 함께 지정
@RequestMapping("URL")단축형 — 모든 HTTP 메서드(GET · POST …)를 받는다
💡 controller/Exam01Controller.java
@Controller
public class Exam01Controller {

    //@RequestMapping(value="/exam01", method=RequestMethod.GET)
    @RequestMapping("/exam01")
    public String requestMethod() {
        return "pages/view01";   // templates/pages/view01.html
    }
}
💡 templates/pages/view01.html
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>RequestMapping 예제</title>
</head>
<body>
    <h2>RequestMapping 예제</h2>
    <p>웹 요청 URL은 /exam01 입니다.</p>
</body>
</html>

6-3. @RestController — 데이터를 직접 반환

📖 @RestController

RESTful 웹 서비스(API)를 만들 때 쓰는 핵심 어노테이션이다. HTML 화면(템플릿)을 반환하는 @Controller + Thymeleaf와 달리, @RestController는 반환값을 응답 본문에 그대로(문자열 · JSON) 보낸다. @Controller + @ResponseBody와 같다.

💡 controller/Exam02Controller.java
@RequestMapping("/exam02")    // 클래스 공통 경로
@RestController
public class Exam02Controller {

    @RequestMapping
    public String requestMethod() {
        return "<h2>@RestController 예제 입니다.</h2>";   // 문자열이 그대로 응답됨
    }
}
@Controller@RestController
반환값의 의미뷰 이름 → templates에서 html을 찾아 렌더링응답 데이터 → 문자열 · JSON 그대로 전송

6-4. @GetMapping — GET 요청 전용

💡 controller/Exam03Controller.java
@Controller
public class Exam03Controller {

    @GetMapping("/exam03")     // = @RequestMapping(value="/exam03", method=RequestMethod.GET)
    public String requestMethod() {
        return "pages/view02";   // templates/pages/view02.html
    }
}
💡 templates/pages/view02.html
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>RequestMapping 예제</title>
</head>
<body>
    <h2>RequestMapping 예제</h2>
    <p>웹 요청 URL은 /exam03 입니다.</p>
</body>
</html>
