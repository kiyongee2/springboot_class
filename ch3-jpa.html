1 스프링과 JPA

🎯 학습목표
  • ORM과 JPA, 하이버네이트의 관계를 설명할 수 있다.
  • SQL을 직접 다루는 방식과 JPA 방식의 차이를 이해한다.

📖 스프링과 JPA

데이터베이스 연동 기술에는 전통적인 JDBC, MyBatis, 하이버네이트 ORM 등이 있다. 하이버네이트 ORM은 SQL까지 프레임워크가 만들어 주기 때문에 개발자가 할 일을 크게 줄여 준다.

용어의미
ORMObject Relational Mapping — 객체지향 구조를 관계형(테이블) 구조로 매핑하는 기술
JPAJava Persistence API — ORM을 Java에서 쉽게 쓰도록 표준화한 스펙(인터페이스)
하이버네이트JPA의 대표 구현체 (그 외 EclipseLink, DataNucleus). 스프링 부트는 기본으로 하이버네이트를 사용
Spring Data JPAJPA를 더 쉽게 쓰도록 스프링이 제공하는 모듈 — 인터페이스만 만들면 CRUD 구현이 자동 생성

1-1. SQL을 직접 다루는 기술

📖 VO 클래스 ↔ 테이블 ↔ SQL

애플리케이션의 데이터를 다시 쓰려면 DB에 저장해야 하고, 이때 SQL이 사용된다. 클래스 · 테이블 · SQL을 모두 개발자가 맞춰 관리해야 한다.

💡 BoardVO.java — VO 클래스
@Getter
@Setter
public class BoardVO {
    private int seq;
    private String title;
    private String writer;
    private String content;
    private Date createDate;
    private int cnt = 0;
}
💡 오라클 DB 테이블 · SQL
CREATE TABLE board(
    seq      NUMBER(5) PRIMARY KEY,
    title    VARCHAR2(200),
    writer   VARCHAR2(20),
    content  VARCHAR2(2000),
    regdate  DATE DEFAULT SYSDATE,
    cnt      NUMBER(5) DEFAULT 0
);

-- 글 등록
INSERT INTO board(seq, title, writer, content) VALUES(seq.nextval, ?, ?, ?);
-- 글 목록 조회
SELECT * FROM board;

1-2. SQL을 직접 다루지 않는 기술

📖 객체를 컬렉션(Map)에 저장한다면?

BoardVO 객체를 Map에 저장하면 코드 어디에도 BOARD 테이블 관련 SQL이 없다. JPA는 이처럼 객체를 컬렉션에 저장 · 관리하는 감각으로 DB를 다루게 해 준다.

💡 BoardVO를 Map에 저장했을 때의 등록 코드
Map<String, BoardVO> boardList = new HashMap<>();

BoardVO board = new BoardVO();
board.setSeq(1);
board.setTitle("테스트 제목...");
board.setWriter("테스터");
board.setContent("테스트 내용입니다...");
board.setCreateDate(new Date());
board.setCnt(0);

//게시글 등록 — SQL이 없다
boardList.put("board", board);

1-3. JPA 동작 원리

Java 애플리케이션
(엔티티 객체)→JPA
(하이버네이트)→JDBC API→데이터베이스

📖 JPA가 대신 해 주는 일

  • 결국 객체를 테이블의 로우(row)와 매핑하려면 누군가 JDBC로 연동해야 한다. JPA는 애플리케이션과 JDBC 사이에서 그 복잡한 절차를 대신 처리한다.
  • 연동 코드뿐 아니라 SQL까지 자동 생성해 DB로 보내고, 결과를 다시 객체로 돌려준다.
  • 클래스 이름 ↔ 테이블 이름, 멤버 변수 ↔ 칼럼을 매핑해서 동작한다.

3 엔티티 매핑 — Board

🎯 학습목표
  • @Entity · @Id · @GeneratedValue · @Column으로 엔티티를 매핑할 수 있다.
  • ddl-auto 설정으로 테이블을 자동 생성하고 Workbench로 확인할 수 있다.

📖 엔티티 매핑 어노테이션

어노테이션의미
@Entity이 클래스를 엔티티로 지정. 기본적으로 클래스 이름과 같은 테이블에 매핑된다.
@Table(name="…")엔티티 이름과 테이블 이름이 다를 때 지정. 같으면 생략
@Id테이블의 기본 키(PK) 매핑 — 없으면 오류
@GeneratedValue@Id 필드에 키 값을 자동 할당. IDENTITY = MySQL auto_increment
@Column칼럼 속성 — nullable=false(NOT NULL), length, unique
@CreationTimestamp저장할 때 현재 시각 자동 입력 (하이버네이트 제공)

3-1. JPA 설정

💡 application.properties — JPA 설정 추가
# JPA 설정
spring.jpa.hibernate.ddl-auto=create
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
ddl-auto 값동작
create실행할 때마다 테이블을 지우고 새로 만든다 (데이터 초기화)
update테이블 유지, 바뀐 칼럼만 반영 (데이터 유지)
none아무것도 안 함 (운영 환경)
⚠️ Spring Boot 4 PPT의 spring.jpa.database-platform=org.hibernate.dialect.MySQL8Dialect는 Hibernate 6부터 deprecated, Hibernate 7(Spring Boot 4)에서는 제거되었다. 이 줄은 쓰지 않는다 — 드라이버를 보고 MySQL 방언을 자동으로 고른다.

3-2. Board 엔티티

💡 model/Board.java
@Builder              // junit 테스트에서 빌더 패턴으로 객체 생성
@NoArgsConstructor    // JPA가 쓰는 기본 생성자
@AllArgsConstructor   // @Builder가 쓰는 전체 필드 생성자
@ToString
@Setter
@Getter
@Entity
public class Board {
    @Id //기본키(Primary Key) 설정
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private int id; //자동 순번

    @Column(nullable = false) //필수 입력
    private String title;   //글 제목

    @Column(length = 20, nullable = false)
    private String writer;  //글쓴이

    @Column(length = 4000, nullable = false)
    private String content; //글 내용

    @CreationTimestamp
    private Timestamp createDate; //작성일
}
⚠️ @Builder와 생성자 PPT는 처음에 @Builder만 붙였다가 목록 조회 테스트에서 “기본 생성자 오류”가 나서 @NoArgsConstructor를 추가한다. JPA 엔티티는 기본 생성자가 반드시 필요하고, @Builder는 전체 필드 생성자가 필요하므로 처음부터 세 개를 함께 붙인다.
🖥️ 콘솔 — 서버 실행 시 하이버네이트가 만든 SQL (ddl-auto=create)
Hibernate: drop table if exists board Hibernate: create table board ( id integer not null auto_increment, create_date datetime(6), writer varchar(20) not null, content varchar(4000) not null, title varchar(255) not null, primary key (id) ) engine=InnoDB
📌 참고 필드 이름 createDate는 칼럼 create_date로 바뀐다(카멜 케이스 → 스네이크 케이스). @Column의 length를 안 쓴 title은 기본 varchar(255).
💡 MySQL Workbench — 테이블 확인
use bootdb;
desc board;
select * from board;

5 쿼리 메서드(Query Method)

🎯 학습목표
  • 메서드 이름 규칙으로 쿼리 메서드를 만들 수 있다.
  • Containing(LIKE) · Or · OrderBy · Pageable · Page<T>를 사용할 수 있다.

📖 쿼리 메서드란?

메서드 이름만으로 필요한 쿼리를 만들어 주는 기능이다. findBy…, getBy…로 시작하고 필드 이름과 키워드를 연결한다. 예) findByAgeOrderByNameDesc()

형식: find + (엔티티 이름) + By + 변수 이름 — 엔티티 이름은 생략 가능. 예) findBoardByTitle() = findByTitle()

키워드예만들어지는 조건
AndfindByLastnameAndFirstname… where lastname = ? and firstname = ?
OrfindByLastnameOrFirstname… where lastname = ? or firstname = ?
BetweenfindByStartDateBetween… where startDate between ? and ?
ContainingfindByTitleContaining… where title like %?%
OrderByfindByAgeOrderByLastnameDesc… order by lastname desc
DistinctfindDistinctByLastnameAndFirstnameselect distinct …

public class QueryMethodTest {

    @Autowired
    private BoardRepository repository;

    @BeforeEach   // 각 테스트 실행 전에 200건 입력
    public void dataPrepare() {
        for(int i=1; i<=200; i++) {
            Board board = new Board();
            board.setTitle("테스트 제목 " + i);
            board.setWriter("테스터");
            board.setContent("테스트 내용 " + i);
            board.setCreateDate(new Timestamp(System.currentTimeMillis()));

            repository.save(board);
        }
    }
}
⚠️ 데이터 누적 @BeforeEach는 테스트 메서드마다 실행된다. ddl-auto=update 상태에서 테스트를 여러 번 돌리면 200건씩 계속 쌓여 결과(개수 · id)가 교안과 달라진다. 결과를 맞추려면 쿼리 메서드 테스트 동안 ddl-auto=create로 바꾸고 테스트를 하나씩 실행한다.

6 연관 관계 매핑 — 다대일 · 양방향

🎯 학습목표
  • 테이블의 PK · FK 관계를 엔티티의 참조 관계로 매핑할 수 있다.
  • @ManyToOne(다대일 단방향)과 @OneToMany(mappedBy)(양방향)를 설정하고 테스트할 수 있다.
  • toString 순환 참조 오류를 막을 수 있다.

📖 연관 관계 매핑

관련 데이터를 여러 테이블에 나눠 저장하고 조인해서 처리한다. 테이블은 PK · FK로 관계를 맺지만, 객체는 참조 변수로 관계를 맺기 때문에 둘이 정확히 일치하지 않는다. 이 차이를 엔티티에 매핑하는 것이 연관 관계 매핑이다.

분류종류
단방향 매핑일대일 단방향, 다대일 단방향, 일대다 단방향
양방향 매핑양방향 매핑 (한쪽은 주인, 한쪽은 mappedBy)

📖 다대일(N:1) — 게시판과 회원

  • 한 명의 회원은 여러 개의 게시글을 작성할 수 있다 → 게시글(N) : 회원(1)
  • 테이블: board.member_id(FK) → member.id(PK)
  • 객체: Board.member 참조 변수로 작성자 정보를 조회한다. 단방향이면 Member는 Board를 모른다.
Board (N)
id · title · content
Member member→──참조──▶→Member (1)
id · memberId · password
name · role
⚠️ 새 프로젝트로 진행 이 단원의 Board는 3 · 4단원의 Board(writer 칼럼 포함)와 구조가 다르다. 같은 프로젝트에 @Entity Board가 두 개 있으면 오류가 나므로 새 프로젝트(예: Spring-JPA-Relation, 패키지 com.springboot)를 만들거나 기존 Board를 아래 코드로 교체한다. 같은 bootdb를 쓰면 기존 board 테이블의 writer NOT NULL 때문에 저장이 실패하므로 Workbench에서 DROP TABLE board; 하거나 처음 실행 시 ddl-auto=create로 실행한다.

6-2. Board 엔티티 — @ManyToOne

💡 entity/Board.java
@ToString
@Setter
@Getter
@Entity
public class Board {
    @Id  //PRIMARY KEY(기본키) - 없으면 에러발생
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;      //번호

    @Column(nullable = false)
    private String title;    //글 제목

    @Column(length = 2000, nullable = false)
    private String content;  //글 내용

    @CreationTimestamp //시간 자동 저장
    private Timestamp createdDate; //작성일

    //다대일 연관 관계 매핑(Board(다) : Member(일))
    //FetchType.LAZY - 게시글 조회시 로딩
    //오류 발생시 - FetchType.EAGER 사용
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn()  //조인 - 참조 관계 (기본 칼럼명: member_id)
    private Member member;
}
설정의미
@ManyToOneBoard(다) : Member(일) 다대일 관계
@JoinColumn(name="member_id")외래키 칼럼 매핑. name을 생략하면 필드명_참조PK = member_id
FetchType.EAGER즉시 로딩 — 게시글을 조회할 때 회원도 함께 조회
FetchType.LAZY지연 로딩 — 회원 정보가 실제로 필요할 때 조회 (권장)
💡 board 테이블 (하이버네이트가 생성)
create table board (
    id int not null auto_increment,
    title varchar(255) not null,
    content varchar(2000) not null,
    created_date datetime(6),
    member_id int,
    primary key (id),
    constraint fk_board_member foreign key (member_id)
    references member (id)
);
