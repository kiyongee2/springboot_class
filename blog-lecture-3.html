1 Spring Security — 회원가입 · 로그인

🎯 학습목표
  • UserDetails / UserDetailsService를 구현해 DB 회원으로 로그인할 수 있다.
  • SecurityFilterChain으로 공개 URL과 인증 필요 URL을 나눌 수 있다.
💡 build.gradle — Spring Security 의존성 추가 (1강에서 빼 둔 Spring Security)
dependencies {
    // 보안
    implementation 'org.springframework.boot:spring-boot-starter-security'
    implementation 'org.thymeleaf.extras:thymeleaf-extras-springsecurity6'
}

📖 로그인 처리 흐름

POST /login (username=이메일, password)→UserDetailService.loadUserByUsername()→BCrypt 비밀번호 비교→세션 생성→/articles 이동

로그인 폼은 Spring Security가 직접 처리하므로 POST /login 컨트롤러는 만들지 않는다. 입력 이름은 반드시 username, password여야 한다.

💡 domain/User.java — UserDetails 구현
@Table(name = "users")   // user는 예약어인 DB가 많아 users 사용
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
@Entity
public class User implements UserDetails {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "id", updatable = false)
    private Long id;

    @Column(name = "email", nullable = false, unique = true)
    private String email;

    @Column(name = "password")
    private String password;

    @Builder
    public User(String email, String password) {
        this.email = email;
        this.password = password;
    }

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        return List.of(new SimpleGrantedAuthority("ROLE_USER"));
    }

    @Override public String getUsername() { return email; }   // 이메일을 로그인 ID로
    @Override public String getPassword() { return password; }
    @Override public boolean isAccountNonExpired() { return true; }
    @Override public boolean isAccountNonLocked() { return true; }
    @Override public boolean isCredentialsNonExpired() { return true; }
    @Override public boolean isEnabled() { return true; }
}
💡 service/UserDetailService.java · UserService.java
// 로그인 시 Spring Security가 호출 — 이메일로 회원 조회
@RequiredArgsConstructor
@Service
public class UserDetailService implements UserDetailsService {
    private final UserRepository userRepository;

    @Override
    public UserDetails loadUserByUsername(String email) {
        return userRepository.findByEmail(email)
                .orElseThrow(() -> new IllegalArgumentException(email));
    }
}

// 회원가입 — 비밀번호는 반드시 암호화해서 저장
@RequiredArgsConstructor
@Service
public class UserService {
    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;

    public Long save(AddUserRequest dto) {
        return userRepository.save(User.builder()
                .email(dto.getEmail())
                .password(passwordEncoder.encode(dto.getPassword()))
                .build()).getId();
    }
}
💡 config/WebSecurityConfig.java
@Configuration
@EnableWebSecurity
public class WebSecurityConfig {

    // 시큐리티 검사 자체를 건너뛸 경로
    @Bean
    public WebSecurityCustomizer configure() {
        return web -> web.ignoring()
                .requestMatchers("/static/**");
    }

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) {
        return http
                .authorizeHttpRequests(auth -> auth
                        .requestMatchers("/login", "/signup", "/user").permitAll()
                        .anyRequest().authenticated())        // 나머지는 로그인 필요
                .formLogin(form -> form
                        .loginPage("/login")
                        .defaultSuccessUrl("/articles", true)) // true: 항상 /articles로
                .logout(logout -> logout
                        .logoutSuccessUrl("/login")
                        .invalidateHttpSession(true))
                .csrf(AbstractHttpConfigurer::disable)       // 학습용으로 CSRF 비활성화
                .build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
💡 controller/UserApiController.java — 회원가입 · 로그아웃
@RequiredArgsConstructor
@Controller
public class UserApiController {
    private final UserService userService;

    @PostMapping("/user")   // signup.html 폼 (name="email", name="password")
    public String signup(AddUserRequest request) {
        userService.save(request);
        return "redirect:/login";
    }

    @GetMapping("/logout")
    public String logout(HttpServletRequest request, HttpServletResponse response) {
        new SecurityContextLogoutHandler().logout(request, response,
                SecurityContextHolder.getContext().getAuthentication());
        return "redirect:/login";
    }
}

2 JWT 토큰 (TokenProvider)

🎯 학습목표
  • JWT의 구조(헤더·페이로드·서명)와 발급·검증 과정을 이해한다.
💡 build.gradle — JWT 의존성 추가
dependencies {
    implementation 'io.jsonwebtoken:jjwt:0.9.1'
    implementation 'javax.xml.bind:jaxb-api:2.3.1'   // jjwt 0.9.x는 Java 11+에서 필요
}
💡 application.yaml — 최상위에 JWT 설정 추가
# JWT 설정은 spring: 아래가 아니라 최상위에 둔다 (@ConfigurationProperties("jwt"))
jwt:
  issuer: sudo-blog
  secret_key: ${JWT_SECRET_KEY:study-springboot}
⚠️ 주의 — YAML은 들여쓰기가 곧 구조다. jwt:를 spring.ai 아래에 두면 키가 spring.ai.jwt.*가 되어 JwtProperties에 값이 들어가지 않는다. 키 이름도 필드명과 같아야 한다(issuer).

📖 개념 및 설명

  • 세션 방식: 서버가 로그인 상태를 기억한다. JWT 방식: 서버가 서명한 토큰을 클라이언트가 들고 다니며 매 요청 Authorization: Bearer 토큰으로 보낸다.
  • 토큰 = 헤더.페이로드.서명. 페이로드에 발급자(iss)·발급일(iat)·만료일(exp)·사용자(sub)·id를 담고, 비밀키로 서명해 위조를 막는다.
  • 현재 프로젝트는 토큰 발급·검증 클래스까지 만든 상태다. 요청마다 토큰을 검사하는 필터는 실습 3에서 완성한다.
💡 config/jwt/JwtProperties.java · TokenProvider.java
@Setter
@Getter
@Component
@ConfigurationProperties("jwt")   // application.yaml의 jwt.issuer, jwt.secret_key
public class JwtProperties {
    private String issuer;
    private String secretKey;
}

@RequiredArgsConstructor
@Service
public class TokenProvider {
    private final JwtProperties jwtProperties;

    // 토큰 발급
    public String generateToken(User user, Duration expiredAt) {
        Date now = new Date();
        return Jwts.builder()
                .setHeaderParam(Header.TYPE, Header.JWT_TYPE)
                .setIssuer(jwtProperties.getIssuer())
                .setIssuedAt(now)
                .setExpiration(new Date(now.getTime() + expiredAt.toMillis()))
                .setSubject(user.getEmail())
                .claim("id", user.getId())
                .signWith(SignatureAlgorithm.HS256, jwtProperties.getSecretKey())
                .compact();
    }

    // 유효성 검증 (서명·만료)
    public boolean validToken(String token) {
        try {
            Jwts.parser().setSigningKey(jwtProperties.getSecretKey()).parseClaimsJws(token);
            return true;
        } catch (Exception e) {
            return false;
        }
    }

    // 토큰 → 인증 정보
    public Authentication getAuthentication(String token) {
        Claims claims = getClaims(token);
        Set<SimpleGrantedAuthority> authorities =
                Collections.singleton(new SimpleGrantedAuthority("ROLE_USER"));
        return new UsernamePasswordAuthenticationToken(
                new org.springframework.security.core.userdetails.User(
                        claims.getSubject(), "", authorities), token, authorities);
    }

    public Long getUserId(String token) {
        return getClaims(token).get("id", Long.class);
    }

    private Claims getClaims(String token) {
        return Jwts.parser().setSigningKey(jwtProperties.getSecretKey())
                .parseClaimsJws(token).getBody();
    }
}

    url: jdbc:mysql://${RDS_HOSTNAME}:${RDS_PORT}/${RDS_DB_NAME}?useSSL=false&serverTimezone=UTC
    username: ${RDS_USERNAME}
    password: ${RDS_PASSWORD}

    hibernate:
      ddl-auto: update        # 운영에서 create-drop 금지 (데이터 삭제됨)

5 Render.com 배포 (Docker + PostgreSQL)

🎯 학습목표
  • Dockerfile로 Spring Boot 앱을 컨테이너 이미지로 만들 수 있다.
  • Render PostgreSQL과 Web Service를 연결해 무료로 배포할 수 있다.
  • 무료 배포 환경의 제약(잠자기, 메모리, 파일 저장)을 설명할 수 있다.

📖 왜 Render?

4단원 AWS Elastic Beanstalk는 설정할 것이 많고 요금이 나올 수 있다. Render는 GitHub 저장소만 연결하면 자동으로 빌드·배포해 주고, 무료 Web Service를 제공해 수업 결과물을 공개 URL로 보여 주기 좋다.

AWS Elastic Beanstalk + RDS (4단원)Render + PostgreSQL (5단원)
배포 방식jar 업로드 또는 GitHub ActionsGitHub push → Dockerfile로 자동 빌드
DBRDS(MySQL)Render PostgreSQL (같은 대시보드에서 생성)
비용프리 티어 이후 과금무료 (제약 있음)
주소xxx.elasticbeanstalk.comhttps://서비스이름.onrender.com (HTTPS 자동)
GitHub push→Render가 Dockerfile 빌드→컨테이너 실행 (profile=prod)→Render PostgreSQL 접속→onrender.com 공개

💡 Dockerfile — 프로젝트 최상위 폴더 (build.gradle 옆)
# ① 빌드 단계: JDK 21로 Gradle 빌드 → 실행 가능한 jar 만들기
FROM eclipse-temurin:21-jdk AS build
WORKDIR /app
COPY . .
RUN chmod +x gradlew && ./gradlew clean bootJar -x test --no-daemon

FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /app/build/libs/*.jar app.jar

# 컨테이너에서는 운영(prod) 프로파일로 실행
ENV SPRING_PROFILES_ACTIVE=prod
# 무료 인스턴스 메모리 512MB에 맞춰 자바 힙 제한

줄의미
FROM ... AS build1단계: JDK가 있는 이미지에서 ./gradlew bootJar로 jar를 만든다 (테스트는 생략 -x test)
FROM eclipse-temurin:21-jre2단계: 실행에 필요한 JRE만 있는 작은 이미지에 jar만 복사 (멀티 스테이지 빌드)
ENV SPRING_PROFILES_ACTIVE=prod컨테이너 안에서는 운영(prod) 설정으로 실행 → Render에 따로 넣지 않아도 된다
-Xmx300m무료 인스턴스 메모리가 512MB라 자바 힙을 제한한다 (메모리 초과로 재시작되는 것 방지)
💡 포트 — Render가 넘겨 주는 PORT는 application.yaml의 server.port: ${PORT:8080}이 받는다. Dockerfile에서 따로 지정하지 않는다.

5-3. application.yaml — 개발(dev) · 운영(prod) 함께 쓰기

💡 src/main/resources/application.yaml — 한 파일에 공통 · dev · prod

---로 문서를 나누고 spring.config.activate.on-profile로 어느 프로파일에서 쓸지 정한다. 맨 위 공통 설정은 항상 적용되고, 실행 중인 프로파일의 설정이 그 위에 덮어써진다.

# =====================================================================
# 공통 설정 — 개발(dev) · 운영(prod) 모두 적용
# =====================================================================
spring:
  application:
    name: blogweb
  profiles:
    default: dev                           # 프로파일을 지정하지 않으면 dev (IntelliJ 실행)

  jpa:
    defer-datasource-initialization: true  # 테이블 생성 후 data.sql 실행
    hibernate:
      ddl-auto: update                     # 테이블 유지, 바뀐 컬럼만 반영 (데이터 유지)
    properties:
      hibernate:
        jdbc:
          time_zone: Asia/Seoul            # created_at 등을 한국 시간으로 저장
    open-in-view: false

  sql:
    init:
      mode: always                         # 시작할 때 data.sql 실행 (중복 방지 SQL)

  datasource:
    driver-class-name: org.postgresql.Driver

server:
  port: ${PORT:8080}                       # Render는 PORT를 넘겨 줌, 로컬은 8080

---
# =====================================================================
# 개발(dev) — 로컬 PostgreSQL, SQL 출력, DevTools
# =====================================================================
spring:
  config:
    activate:
      on-profile: dev

  datasource:
    url: jdbc:postgresql://localhost:5432/springdb
    username: javauser                     # pgAdmin(psql)에서 만든 계정
    password: ${DB_PASSWORD}               # IntelliJ 실행 설정 → Environment variables

  jpa:
    show-sql: true                         # 실행 SQL 출력(학습용)
    properties:
      hibernate:
        format_sql: true

  devtools:
    restart:
      enabled: true                        # 코드 변경 시 서버 자동 재시작
      poll-interval: 2s                    # 변경 확인 간격
      quiet-period: 1s                     # 변경이 멈춘 뒤 재시작까지 대기
      additional-exclude: uploads/**       # 업로드 폴더 변경은 재시작 안 함
    livereload:
      enabled: true                        # 브라우저 자동 새로고침 (포트 35729)

  thymeleaf:
    cache: false                           # 템플릿 수정이 바로 반영

---
# =====================================================================
# 운영(prod) — Render 배포. 접속 정보는 모두 환경변수로
# =====================================================================
spring:
  config:
    activate:
      on-profile: prod

  datasource:
    url: ${DB_URL}                         # jdbc:postgresql://호스트:5432/springdb
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}

  jpa:
    show-sql: false                        # 운영에서는 SQL 출력 끔

  thymeleaf:
    cache: true                            # 템플릿 캐시 사용 (성능)
개발 (dev)운영 (prod)
언제IntelliJ에서 실행 (profiles.default: dev)Docker 컨테이너 (ENV SPRING_PROFILES_ACTIVE=prod)
DBlocalhost:5432/springdb, 비밀번호만 환경변수URL · 계정 · 비밀번호 모두 환경변수 (Render PostgreSQL)
SQL 출력켬 (show-sql, format_sql)끔
DevTools · 템플릿 캐시자동 재시작 · 캐시 끔DevTools 없음(jar에서 빠짐) · 캐시 켬
포트8080Render의 PORT
💡 로컬에서 prod 미리 실행해 보기 — IntelliJ 실행 설정 Environment variables에 SPRING_PROFILES_ACTIVE=prod;DB_URL=jdbc:postgresql://localhost:5432/springdb;DB_USERNAME=javauser;DB_PASSWORD=…를 넣으면 운영 설정으로 실행된다. 콘솔에 The following 1 profile is active: "prod"가 보인다.
⚠️ 비밀번호는 파일에 쓰지 않는다 — 모든 비밀 값은 ${...}로만 받는다. GitHub에 올라가도 안전하다.

5-4. Render PostgreSQL 만들기

🐘 Render PostgreSQL (Free)

로컬에서 PostgreSQL로 개발한 blogweb(postgresql) 프로젝트를 배포한다 (1강 3-5: PostgreSQL 드라이버, FROM DUAL 없는 data.sql).

  1. Render 대시보드 → New + → Postgres
  2. Name blogdb, Database springdb, User javauser 입력 → Region Singapore (Web Service와 같은 지역) → Instance Type Free → Create Database
  3. 상태가 Available이 되면 Info → Connections에서 Hostname, Port, Database, Username, Password 확인
Render 환경변수값
DB_URLjdbc:postgresql://Hostname:5432/springdb
DB_USERNAMEjavauser
DB_PASSWORDConnections 화면의 Password
⚠️ URL 형식 주의 — Render가 보여 주는 postgresql://user:pass@host/db는 JDBC 형식이 아니다. 그대로 넣으면 DB에 접속하지 못해 Render Logs에 Driver org.postgresql.Driver claims to not accept jdbcUrl, 이어서 Unable to determine Dialect without JDBC metadata 오류가 나고 앱이 멈춘다. 맨 앞에 jdbc:를 붙이고 호스트 뒤에 :5432를 넣어 jdbc:postgresql://호스트:5432/DB이름으로 바꾸며, 계정·비밀번호는 따로 넣는다.
postgresql://javauser:비밀번호@dpg-xxxx-a/springdb      ← Render 화면 (그대로 X)
jdbc:postgresql://dpg-xxxx-a:5432/springdb              ← DB_URL에 넣을 값
💡 Internal vs External — Web Service와 DB가 같은 Region이면 Internal Hostname(dpg-xxxx-a)으로 빠르게 접속한다. pgAdmin으로 내 PC에서 들여다볼 때는 External Hostname(....singapore-postgres.render.com)을 쓴다.

5-5. Render Web Service 만들기

☁️ Render 대시보드
  1. Dockerfile · .dockerignore · application.yaml(dev/prod)을 추가·수정했으면 git add . → git commit → git push (5-1 참고)
  2. render.com → GitHub 계정으로 가입 → New + → Web Service → 저장소 선택(Connect)
  3. 아래 표대로 입력 → Deploy Web Service
  4. Logs 탭에서 빌드 → Started BlogwebApplication 로그 확인 (첫 빌드는 5~10분)
  5. https://서비스이름.onrender.com/articles 접속 → 샘플 글 3개가 보이면 성공
항목값
Nameblogweb (주소가 blogweb-xxxx.onrender.com이 된다)
LanguageDocker (Build/Start Command는 비워 둔다 — Dockerfile이 처리)
Branch / Root Directorymain / 비워 둠 (Dockerfile이 있는 최상위)
RegionSingapore (한국에서 가장 가까움)
Instance TypeFree (512MB RAM, 0.1 CPU)

5-6. 무료 플랜 주의사항

⚠️ 알고 쓰기
  • 잠자기: 무료 Web Service는 15분 동안 요청이 없으면 멈추고, 다음 요청 때 다시 켜지느라 약 1분 기다린다. 수업 시연 전에 미리 한 번 접속해 둔다.
  • 메모리 512MB: Spring Boot는 메모리를 많이 쓴다. JAVA_OPTS=-Xmx300m을 지키고, 로그에 Out of memory가 보이면 값을 줄인다.
  • 업로드 이미지: 컨테이너가 다시 시작·재배포되면 uploads/ 폴더 파일이 사라진다. 오래 보관하려면 S3 같은 외부 저장소를 쓴다.
  • 무료 DB 만료: 무료 PostgreSQL은 만든 지 30일이 지나면 만료되고, 유예 기간 뒤 삭제된다. 수업용으로 쓰고 필요하면 새로 만든다.
  • 빌드 시간: 무료 플랜은 한 달 빌드 시간이 정해져 있으므로 작은 수정마다 push하지 말고 모아서 올린다.
