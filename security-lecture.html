1 인증과 인가 · 기본 로그인

🎯 학습목표
  • 인증(Authentication)과 인가(Authorization)의 차이를 설명할 수 있다.
  • Spring Security 의존성을 추가하고 기본 로그인 화면이 동작하는 원리를 이해한다.
  • SecurityFilterChain 빈을 등록하면 기본 동작이 바뀐다는 것을 확인한다.

📖 인증과 인가

구분의미회사 비유
인증 (Authentication)“너 누구야?” — 사용자가 누구인지 확인하는 과정 (로그인)출입문에서 사원증 · RFID 카드를 찍어 신원을 확인
인가 (Authorization)“너 이거 해도 돼?” — 확인된 사용자에게 권한이 있는지 검사직급 · 직무에 따라 들어갈 수 있는 방(자원)이 다름
요청→인증 (로그인했나?)→인가 (권한 있나?)→자원 접근 허용 / 거부(403)

1-3. 기본 로그인 화면 확인

📖 의존성만 추가하면 모든 URL이 잠긴다

시큐리티를 추가하고 재실행하면 콘솔에 임시 비밀번호가 출력되고, 어떤 URL에 접속해도 기본 로그인 폼(/login)으로 이동합니다. 아이디는 user, 비밀번호는 콘솔에 찍힌 값입니다.

📖 공식 가이드 — Securing a Web Application

spring.io → Projects → Spring Security → LEARN 탭 → Guides의 “Securing a Web Application”에서 지금 배우는 흐름(기본 로그인 → SecurityFilterChain → In-Memory 사용자)을 그대로 따라 해 볼 수 있습니다. 가이드는 항상 최신 버전(현재 Spring Security 7.1.2) 기준으로 작성됩니다.

💡 공식 가이드의 WebSecurityConfig.java (Spring Security 7.1.2)
@Configuration
@EnableWebSecurity
class WebSecurityConfig {

    @Bean
    SecurityFilterChain securityFilterChain(HttpSecurity http) {
        http
            .authorizeHttpRequests((requests) -> requests
                .requestMatchers("/", "/home").permitAll()   // 누구나
                .anyRequest().authenticated()                // 나머지는 로그인 필요
            )
            .formLogin((form) -> form
                .loginPage("/login")                         // 사용자 정의 로그인 화면
                .permitAll()
            )
            .logout(LogoutConfigurer::permitAll);            // 로그아웃 누구나 허용

        return http.build();
    }

    @Bean
    PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    UserDetailsService userDetailsService(PasswordEncoder encoder) {
        String password = encoder.encode("password");
        UserDetails user = User.withUsername("user").password(password).roles("USER").build();
        return new InMemoryUserDetailsManager(user);
    }
}
📌 가이드 코드에서 눈여겨볼 점 ① Security 7에서는 securityFilterChain(HttpSecurity http)에 throws Exception이 없어도 됩니다. (붙여도 동작은 같음)
② PasswordEncoder를 메서드 파라미터로 주입받아 사용합니다. 2-4의 passwordEncoder() 직접 호출 방식과 결과는 같습니다.
③ LogoutConfigurer::permitAll은 logout(logout -> logout.permitAll())을 줄여 쓴 메서드 참조입니다.

1-4. SecurityFilterChain 빈 등록

📖 설정 클래스를 만들면 기본 로그인이 사라진다

SecurityFilterChain 빈을 직접 등록하면 스프링 부트의 기본 보안 설정이 꺼집니다. 아래처럼 규칙 없이 http.build()만 반환하면 로그인 없이 모든 페이지에 접근됩니다. 이제 이 메서드 안에 규칙을 하나씩 채워 나갑니다.

💡 config/WebSecurityConfig.java
@Configuration
@EnableWebSecurity
public class WebSecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http.build();
    }
}

2-1. SecurityConfig — 권한별 접근 규칙

💡 config/SecurityConfig.java
@EnableWebSecurity
@Configuration
public class SecurityConfig {

    @Bean
    SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth        // 해당 경로만 허용
                .requestMatchers("/", "/auth", "/home/**").permitAll()
                .requestMatchers("/user/**").hasAnyRole("USER", "ADMIN")
                .requestMatchers("/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated()          // 나머지는 인증 필요
            )
            .formLogin(form -> form
                .loginPage("/login")                   // 사용자 로그인 페이지
                .permitAll()                           // 누구나 접근 가능
            )
            .logout(logout -> logout                   // 로그아웃
                .logoutRequestMatcher(
                    PathPatternRequestMatcher.withDefaults().matcher(HttpMethod.GET, "/logout"))
                .logoutSuccessUrl("/auth")
                .invalidateHttpSession(true)
                .deleteCookies("JSESSIONID")
            );
        return http.build();
    }
}
⚠️ Boot 4 / Security 7 원본 PPT(Boot 3.5)는 new AntPathRequestMatcher("/logout", "GET")를 사용합니다. AntPathRequestMatcher는 Spring Security 6.5(Boot 3.5)에서 deprecated, Security 7(Boot 4)에서 삭제되었으므로 위처럼 PathPatternRequestMatcher를 사용하세요. (Boot 3.5에서도 동일)
import: org.springframework.security.web.servlet.util.matcher.PathPatternRequestMatcher, org.springframework.http.HttpMethod
📌 참고 hasRole("USER")는 내부적으로 ROLE_USER 권한을 검사합니다. 그래서 DB에는 ROLE_ 접두어를 붙여 저장합니다.

@EnableWebSecurity
@Configuration
public class SecurityConfig {

    SecurityFilterChain filterChain(HttpSecurity http) throws Exception {

3-3. Entity · DTO · Repository

💡 entity/Member.java
@Data
@Entity
public class Member {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(unique = true)
    private String email;

    @Column(nullable = false)
    private String passwd;

    @Column(length = 30, nullable = false)
    private String name;

    @Column(length = 10)
    private String gender;

    @Column(nullable = false)
    private String role;

    @CreationTimestamp
    private Timestamp joinDate;

    // DTO를 Entity로 변환
    public static Member toSaveEntity(MemberDTO dto, PasswordEncoder pwEncoder) {
        Member member = new Member();
        member.setEmail(dto.getEmail());
        member.setPasswd(pwEncoder.encode(dto.getPasswd()));  // 암호화 저장
        member.setName(dto.getName());
        member.setGender(dto.getGender());
        member.setRole("ROLE_USER");          // 관리자는 ROLE_ADMIN
        return member;
    }
}

3-4. MemberService

💡 service/MemberService.java
@RequiredArgsConstructor
@Service
public class MemberService {

    private final MemberRepository repository;
    private final PasswordEncoder pwEncoder;

    // 회원 가입
    public void save(MemberDTO dto) {
        if (repository.findByEmail(dto.getEmail()).isPresent()) {
            throw new IllegalArgumentException("이미 존재하는 이메일입니다.");
        }
        Member member = Member.toSaveEntity(dto, pwEncoder);
        repository.save(member);
    }

    // 회원 목록
    public List<Member> findAll() {
        return repository.findAll();
    }

    // 회원 정보
    public Member findById(Long id) {
        return repository.findById(id)

4 UserDetailsService · DB 로그인

🎯 학습목표
  • UserDetails / UserDetailsService의 역할을 설명할 수 있다.
  • CustomUserDetails, CustomUserDetailsService를 구현해 DB 회원으로 로그인할 수 있다.
  • DaoAuthenticationProvider를 이용한 로그인 처리 흐름을 이해한다.

📖 UserDetailsService가 필요한 이유

시큐리티의 인증 관리자는 로그인 요청이 오면 UserDetailsService에게 “이 아이디의 사용자 정보(UserDetails)를 줘”라고 요청합니다. 기본 구현은 아이디 user + 콘솔 비밀번호 한 명뿐이므로, DB 회원으로 로그인하려면 UserDetailsService를 직접 구현해서 Member를 조회해 돌려줘야 합니다.

클래스역할
CustomUserDetailsMember를 감싸 UserDetails 형태로 제공 (아이디 · 비밀번호 · 권한)
CustomUserDetailsServiceloadUserByUsername()에서 이메일로 Member 조회
DaoAuthenticationProviderUserDetailsService로 사용자를 가져오고 PasswordEncoder로 비밀번호 검증

4-2. CustomUserDetailsService

💡 service/CustomUserDetailsService.java
@RequiredArgsConstructor
@Service
public class CustomUserDetailsService implements UserDetailsService {

    private final MemberRepository repository;

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        Member member = repository.findByEmail(username)
                .orElseThrow(() -> new UsernameNotFoundException("사용자를 찾을 수 없습니다."));
        return new CustomUserDetails(member);
    }
}

4-3. SecurityConfig (DB 로그인)

💡 config/SecurityConfig.java
@Configuration
@EnableWebSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final CustomUserDetailsService userDetailsService;

    @Bean  // 비밀번호 암호화
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean  // 로그인 인증 시 필요
    public DaoAuthenticationProvider authenticationProvider(PasswordEncoder encoder) {
        DaoAuthenticationProvider authProvider =
                new DaoAuthenticationProvider(userDetailsService);   // 계정 설정
        authProvider.setPasswordEncoder(encoder);                     // 비밀번호 설정
        return authProvider;
    }

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/", "/members/join", "/members/login", "/boards/pages",
                                 "/css/**", "/js/**", "/images/**").permitAll()
                .requestMatchers("/admin/**").hasRole("ADMIN")
                .requestMatchers("/members/**").hasAnyRole("USER", "ADMIN")
                .anyRequest().authenticated()
            )
            .formLogin(form -> form
                .loginPage("/members/login")
                .loginProcessingUrl("/login")        // 로그인 POST 액션 URL
                .defaultSuccessUrl("/", true)
                .permitAll()
            )
            .logout(logout -> logout
                .logoutRequestMatcher(
                    PathPatternRequestMatcher.withDefaults().matcher(HttpMethod.GET, "/logout"))
                .logoutSuccessUrl("/")
                .invalidateHttpSession(true)
                .deleteCookies("JSESSIONID")
            );
        return http.build();
    }
}
⚠️ Boot 4 / Security 7 원본 PPT(Boot 3.5)는 new DaoAuthenticationProvider() 후 setUserDetailsService(userDetailsService)를 호출합니다. 기본 생성자와 setter는 Security 6.3부터 deprecated, Security 7(Boot 4)에서 삭제되었으므로 위처럼 생성자 인자로 전달하세요. (Boot 3.5에서도 동일)
⚠️ 규칙 순서 · 경로 requestMatchers는 위에서부터 먼저 일치하는 규칙이 적용됩니다. "/members/**"(USER)가 "/members/join"(permitAll)보다 위에 있으면 가입 화면도 막히므로 구체적인 경로를 먼저 적습니다. PPT의 이미지 경로는 /img/**지만 프로젝트 폴더는 static/images이므로 /images/**로 맞췄습니다.

4-5. 로그인 처리 흐름

POST /login
(username, password)→DaoAuthenticationProvider→userDetailsService
.loadUserByUsername()→BCryptPasswordEncoder
.matches()→Authentication 생성
→ 세션 저장
단계설명
1사용자가 로그인 폼에서 /login으로 POST 요청
2DaoAuthenticationProvider가 loadUserByUsername() 호출 → DB에서 이메일로 Member 조회 → CustomUserDetails 반환
3BCryptPasswordEncoder.matches(입력값, DB암호)로 비밀번호 비교
4성공하면 Authentication 객체가 생성되어 SecurityContext(세션)에 저장 → defaultSuccessUrl("/")로 이동

💡 config/SecurityConfig.java — formLogin 수정
            .formLogin(form -> form
                .loginPage("/members/login")
                .usernameParameter("email")       // 아이디 파라미터 이름
                .passwordParameter("passwd")      // 비밀번호 파라미터 이름
                .loginProcessingUrl("/login")     // 로그인 POST 액션 URL
                .defaultSuccessUrl("/", true)
                .permitAll()
            )
📌 참고 파라미터 이름만 바뀔 뿐, loadUserByUsername(String username)에는 email 값이 그대로 전달됩니다.

📖 📋 전체 정리

단원핵심
1인증 = 누구인지 확인 / 인가 = 권한 확인, starter-security 추가 시 전체 잠금
2SecurityFilterChain: authorizeHttpRequests · formLogin · logout, In-Memory 사용자
3Member 가입 시 PasswordEncoder(BCrypt)로 암호화, role = ROLE_USER
4UserDetails · UserDetailsService 구현 + DaoAuthenticationProvider = DB 로그인
5sec:authorize, sec:authentication, ${#authentication}
6/admin/** = ADMIN, exceptionHandling().accessDeniedPage()
7usernameParameter / passwordParameter
7장. 스프링부트 시큐리티 · 학습 교안
