1 타임리프(Thymeleaf)란?

🎯 학습목표
  • 타임리프가 무엇이고 JSP와 비교해 어떤 장점이 있는지 설명할 수 있다.
  • html 문서에 타임리프 네임스페이스를 선언하고 기본 문법(th:text · th:each · th:if · th:href)을 사용할 수 있다.

📖 타임리프(Thymeleaf)란?

  • 서버 사이드 Java 템플릿 엔진 — HTML 파일에 Java 데이터를 연결해 동적으로 화면을 만든다.
  • HTML을 그대로 브라우저에서 열어도 깨지지 않는다(내추럴 템플릿) → 프론트엔드와 협업이 쉽다.
  • 표현식 문법이 단순하다 (th:text, th:each 등).
  • Spring MVC와 자연스럽게 통합된다 (Model 객체 데이터 바인딩).
  • 다른 템플릿 엔진: Freemarker, Mustache, Groovy Templates 등. JSP보다 장점이 많아 스프링 부트의 기본 추천 엔진이다.

📖 공식 문서

www.thymeleaf.org → Docs → Tutorials → Using Thymeleaf (Read online · PDF)

📖 사용 방법

html 태그에 네임스페이스를 선언하고 th: 속성을 쓴다. 의존성은 1장에서 추가한 spring-boot-starter-thymeleaf이다.

💡 타임리프 선언
<html xmlns:th="http://www.thymeleaf.org">
문법의미예
th:text="${변수}"텍스트 출력 (HTML 태그는 글자로)<h3 th:text="${message}"></h3>
th:utext="${변수}"HTML 태그를 해석해서 출력<p th:utext="${data2}"></p>
[[${변수}]]태그 안에 바로 출력 (인라인)<h2>[[${data1}]]</h2>
th:each="item : ${list}"반복문<tr th:each="m : ${members}">
th:if / th:unless조건문<p th:if="${list.isEmpty()}">
th:href="@{/경로}"링크 (앱 주소 기준)<a th:href="@{/time}">
th:src · th:action이미지 · 폼 전송 경로<form th:action="@{/login}">

2 Model로 데이터 전달 · 메인 페이지 타임리프 적용

🎯 학습목표
  • 컨트롤러에서 Model에 데이터를 담아 뷰로 전달할 수 있다.
  • 1장의 메인 페이지를 타임리프 문법(th:href · th:src · th:text)으로 바꿀 수 있다.

2-1. Model 인터페이스로 데이터 전달

📖 Model

요청 처리 메서드의 매개변수로 Model을 받고 model.addAttribute("이름", 값)으로 데이터를 담으면, 뷰(템플릿)에서 ${이름}으로 꺼내 쓸 수 있다.

컨트롤러
model.addAttribute("data1", …)→뷰 이름 반환→템플릿
${data1}

3 요청 파라미터 — @RequestParam · @PathVariable

🎯 학습목표
  • @RequestParam으로 쿼리 문자열(?이름=값)을 받을 수 있다.
  • @PathVariable로 URL 경로 안의 값을 받을 수 있다.
  • th:text와 th:utext의 차이를 설명할 수 있다.

3-1. 요청 파라미터와 @RequestParam

📖 요청 파라미터(request parameter)

GET 방식에서 URL 뒤에 ?이름=값 형태로 보내는 데이터다. 예) http://…/search?q=전기차 → 파라미터 이름 q, 값 전기차. 여러 개는 &로 잇는다.

@RequestParam("이름")은 같은 이름의 파라미터 값을 매개변수로 받아 오며, 매개변수 타입(String · int · Long …)에 맞게 자동 변환한다.

💡 controller/Ex01Controller.java
@Controller
public class Ex01Controller {

    @GetMapping("/ex01")   // /ex01?id=space&pw=12345
    public String method1(@RequestParam("id") String userId,
                          @RequestParam("pw") String userPw,
                          Model model) {
        model.addAttribute("data1", "@RequestParam 예제");
        model.addAttribute("data2", "id:" + userId + "<br>pw:" + userPw);
        return "pages/viewPage01";
    }
}
💡 templates/pages/viewPage01.html
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
<meta charset="UTF-8">
<title>요청 파라미터</title>
</head>
<body>
    <h2 th:text="${data1}"></h2>
    <p th:utext="${data2}"></p>   <!-- <br>을 줄바꿈으로 해석 -->
</body>
</html>
📌 th:text vs th:utext th:text는 <br>을 글자 그대로 보여 주고(보안상 안전), th:utext는 HTML로 해석해 줄바꿈이 된다. 사용자가 입력한 값을 th:utext로 출력하면 스크립트가 실행될 수 있으므로(XSS) 꼭 필요할 때만 쓴다.
⚠️ 파라미터를 빼면 400 @RequestParam은 기본이 필수라서 /ex01처럼 파라미터 없이 요청하면 400 Bad Request가 난다. 선택 값으로 받으려면 @RequestParam(value="id", required=false) 또는 defaultValue="guest"를 쓴다.

3-2. 경로 변수와 @PathVariable

📖 경로 변수

URL 경로 안에 들어 있는 값을 받을 때 쓴다. 매핑 경로에 중괄호 { }로 이름을 정하고 @PathVariable("이름")으로 받는다. 예) http://localhost:8080/boards/1 → 경로 변수 값 1

💡 형식
@GetMapping("/../{경로_변수}")
public String method1(@PathVariable("경로_변수") 매개변수) {
    . . .
}
💡 controller/Ex02Controller.java
@Controller
public class Ex02Controller {

    @GetMapping("/boards/{id}")
    public String method1(@PathVariable("id") Long id,
                          Model model) {
        model.addAttribute("data1", "@PathVariable 예제");
        model.addAttribute("data2", "글번호: " + id);
        return "pages/viewPage02";
    }
}
💡 templates/pages/viewPage02.html
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
<meta charset="UTF-8">
<title>경로 변수</title>
</head>

    <h2 th:text="${data1}"></h2>
    <p th:text="${data2}"></p>
</body>
</html>

4 롬복(Lombok) · @ModelAttribute

🎯 학습목표
  • 롬복(Lombok)으로 Getter · Setter · 생성자 · toString을 자동 생성할 수 있다.
  • @ModelAttribute로 폼 데이터를 객체(DTO)에 한 번에 담을 수 있다.

4-1. 롬복(Lombok) 라이브러리

📖 롬복이란?

Getter, Setter, 생성자, toString처럼 단순 반복되는 코드를 어노테이션 하나로 자동 생성해 주는 라이브러리다. 1장에서 프로젝트를 만들 때 Lombok을 체크했으므로 build.gradle에 이미 들어 있다.

💡 build.gradle — Lombok (이미 추가됨)
dependencies {
    compileOnly 'org.projectlombok:lombok'
    annotationProcessor 'org.projectlombok:lombok'
    // 테스트 코드에서도 롬복(@Slf4j 등)을 쓰려면
    testCompileOnly 'org.projectlombok:lombok'
    testAnnotationProcessor 'org.projectlombok:lombok'
}
💡 IntelliJ는 설치 불필요 이클립스/STS는 lombok.jar를 내려받아 java -jar lombok.jar로 IDE에 설치해야 하지만, IntelliJ는 Lombok 플러그인이 기본 내장되어 있어 설치가 필요 없다. 처음 열 때 “Enable annotation processing?” 알림이 뜨면 Enable을 누르거나, Settings → Build, Execution, Deployment → Compiler → Annotation Processors → Enable annotation processing을 체크한다.
어노테이션생성되는 코드
@Getter / @Setter모든 필드의 getXxx() / setXxx()
@NoArgsConstructor기본 생성자
@AllArgsConstructor모든 필드를 받는 생성자
@ToString필드 값을 보여 주는 toString()
@Data@Getter + @Setter + @ToString + @EqualsAndHashCode + @RequiredArgsConstructor
💡 dto/User.java
import lombok.AllArgsConstructor;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;
import lombok.ToString;

@AllArgsConstructor  //매개변수를 모두 가진 생성자
@NoArgsConstructor   //기본 생성자
@ToString            //문자열 정보
@Setter              //setter
@Getter              //getter
public class User {
    private String id;   //아이디
    private String pw;   //비밀번호
}
🔍 생성된 메서드 확인 IntelliJ 왼쪽 아래 Structure 탭(Alt+7)을 열면 롬복이 만든 User(), User(String, String), getId(), setPw(), toString() 등을 확인할 수 있다.

4-2. @ModelAttribute로 폼 데이터 받기

📖 @ModelAttribute

폼의 name 속성과 같은 이름의 필드에 값을 자동으로 넣어 준다. @ModelAttribute User user → 폼의 name="id", name="pw" 값이 setId(), setPw()로 들어간다. (그래서 DTO에 기본 생성자 + Setter가 필요하다)

항목@RequestParam@ModelAttribute
사용 대상개별 파라미터객체(DTO / VO)
코드 양파라미터마다 선언필드 자동 매핑
유지 보수파라미터가 많으면 불편필드 추가 시 편리
예시@RequestParam("id") String id@ModelAttribute User user
💡 controller/Ex03Controller.java
@Controller
public class Ex03Controller {

    // 입력 폼 페이지
    @GetMapping("/userForm")
    public String formPage() {
        return "pages/userForm";

}

5-1. MemberDTO — 자료형 클래스

💡 롬복 없이 작성하면 (참고)
public class Member {
    private Long id;
    private String name;
    private String email;

    public Member() {}

    public Member(Long id, String name, String email) {
        this.id = id;
        this.name = name;
        this.email = email;
    }

    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }
}
💡 dto/MemberDTO.java — 롬복 사용
@ToString            //문자열 정보
@NoArgsConstructor   //기본 생성자
@AllArgsConstructor  //매개변수를 모두 가진 생성자
@Setter              //setter
@Getter              //getter
public class MemberDTO {
    private Long id;       //순번
    private String name;   //이름
    private String email;  //이메일
}

5-2. MemberRepository — 자료 저장(DAO)

💡 repository/MemberRepository.java
@Repository
public class MemberRepository {

    private List<MemberDTO> list = new ArrayList<>();
    private long sequence = 0L;

    //회원 등록
    public MemberDTO save(MemberDTO dto) {
        dto.setId(++sequence);   // 1, 2, 3 … 순번 부여
        list.add(dto);
        return dto;
    }

    //회원 목록
    public List<MemberDTO> findAll() {
        return list;
    }
}

5-3. MemberController — 컨트롤러

💡 controller/MemberController.java
@RequestMapping("/members")   // 공통 경로
@RequiredArgsConstructor       // final 필드 생성자 주입
@Controller
public class MemberController {

    private final MemberRepository repository;

    //회원 등록 화면
    @GetMapping("/add")
    public String addForm() {
        return "member/add";        // templates/member/add.html
    }

    //회원 등록 처리
    @PostMapping("/add")
    public String add(@ModelAttribute MemberDTO dto) {
        //System.out.println("MemberDTO: " + dto);
        repository.save(dto);
        return "redirect:/members";  // 목록으로 이동 (새로고침 시 중복 등록 방지)
    }

    //회원 목록 보기
    @GetMapping
    public String list(Model model) {
        List<MemberDTO> members = repository.findAll();
        model.addAttribute("members", members);
        return "member/members";     // templates/member/members.html
    }
}
💡 의존성 주입 방식 PPT는 @Autowired private MemberRepository repository;(필드 주입)를 사용한다. 동작은 같지만 실무에서는 final 필드 + @RequiredArgsConstructor(생성자 주입)를 권장한다. IntelliJ도 필드 주입에 “Field injection is not recommended” 경고를 띄운다.

회원 관리 확인

  1. localhost:8080/members 접속 → 빈 목록 확인
  2. 회원 등록 → 이름 · 이메일 입력 → 등록 → 목록에 ID 1번으로 추가되는지 확인
  3. 한 명 더 등록 → ID 2번 확인
  4. 서버 재시작 후 목록이 비는 것 확인 (메모리 저장) → 3장에서 DB(JPA)로 저장
