1 인증이란? — 세션과 토큰

🎯 학습목표
  • HTTP가 요청마다 "누구인지" 기억하지 못한다는 것을 이해한다.
  • 11강 로그인 방식의 한계(새로고침 로그아웃, 서버 API 무방비)를 설명할 수 있다.
  • 세션 인증과 JWT 토큰 인증의 차이를 설명할 수 있다.

📖 11강 로그인 방식의 문제

11강에서는 로그인에 성공하면 서버가 돌려준 회원 정보를 React의 currentUser(메모리)에만 저장했습니다. 그래서 세 가지 문제가 있습니다.

문제이유
새로고침하면 로그아웃currentUser는 메모리 상태라 새로고침하면 처음 값(null)으로 돌아감
서버 API가 무방비서버는 요청을 보낸 사람이 누구인지 모름 → Postman으로 누구나 상품을 등록 · 수정 · 삭제 가능
관리자 확인이 화면에만 있음버튼을 숨겨도 주소창이나 Postman으로 우회 가능

HTTP는 요청 하나하나가 따로따로입니다(무상태, stateless). 서버가 "이 요청은 로그인한 user1이 보냈다"는 것을 알려면, 로그인 뒤 요청마다 나를 증명하는 값을 함께 보내야 합니다. 이것을 인증(Authentication)이라고 합니다.

📖 세션 인증 vs JWT 토큰 인증

세션(Session)JWT 토큰(JSON Web Token)
로그인 정보 저장 위치서버 (세션 저장소)토큰 안에 담아 브라우저가 보관
브라우저가 보내는 것세션 ID가 든 쿠키 (자동 전송)Authorization: Bearer 토큰 헤더 (직접 붙임)
서버가 확인하는 방법세션 ID로 저장소에서 회원 정보 찾기비밀키로 서명 · 만료 시간 확인
로그아웃서버에서 세션 삭제 → 바로 무효브라우저에서 토큰 삭제 (토큰 자체는 만료 전까지 유효)
서버가 여러 대일 때세션 저장소를 공유해야 함 (DB · Redis)비밀키만 같으면 어느 서버든 확인 가능
Express 라이브러리express-sessionjsonwebtoken

2단원은 세션, 3단원은 JWT로 같은 기능(새로고침 로그인 유지, 관리자 API 보호)을 만듭니다. 둘 다 11강을 마친 코드에서 시작하며, 실제 프로젝트에서는 둘 중 하나만 씁니다.

📖 미들웨어(middleware)

Express에서 요청이 라우터 함수에 닿기 전에 먼저 실행되는 함수입니다. (req, res, next)를 받아서, 통과시키려면 next()를 부르고 막으려면 바로 응답(res.status(401)…)을 보냅니다. app.use(express.json()), app.use(cors())도 미들웨어입니다. 이번 강의에서는 로그인 확인 · 관리자 확인 미들웨어를 직접 만듭니다.

요청 → cors → express.json → requireLogin → requireAdmin → 라우터 함수 → 응답 │(로그인 안 함) │(관리자 아님) ▼ 401 ▼ 403

2 세션 인증 (express-session)

🎯 학습목표
  • express-session으로 로그인 정보를 서버 세션에 저장할 수 있다.
  • 미들웨어로 로그인 · 관리자 권한이 필요한 API를 막을 수 있다.
  • React에서 쿠키를 함께 보내고(withCredentials), 새로고침해도 로그인을 유지할 수 있다.

📖 세션 인증 흐름

[로그인] 브라우저 ── POST /api/users/login (아이디 · 비밀번호) ──▶ 서버 서버: 비밀번호 확인 → req.session.user = 회원 정보 (서버 메모리에 저장) ◀── Set-Cookie: connect.sid=세션ID ── [다음 요청부터] 브라우저 ── 요청 + Cookie: connect.sid=세션ID (자동으로 붙음) ──▶ 서버 서버: 세션ID로 req.session.user를 찾음 → 누구인지 앎

쿠키(cookie)는 서버가 브라우저에 맡겨 두는 작은 값입니다. 한 번 받으면 브라우저가 같은 서버로 요청할 때마다 자동으로 함께 보냅니다. 세션 방식은 쿠키에 회원 정보가 아니라 세션 ID(번호표)만 넣고, 실제 회원 정보는 서버가 가지고 있습니다.

import express from 'express'
import pg from 'pg'
import cors from 'cors'

server/index.js (app 아래, 라우터 위) 
// 쿠키를 주고받으려면 허용할 주소(origin)를 정확히 적고 credentials를 켭니다.
app.use(cors({
  origin: "http://localhost:5173",
  credentials: true
}));

// 세션 설정: 로그인 정보를 서버 메모리에 저장하고, 브라우저에는 세션 ID 쿠키만 보냅니다.
app.use(session({
  secret: "space-shop-secret",   // 세션 ID 쿠키를 서명하는 비밀 키
  resave: false,                 // 바뀐 것이 없으면 다시 저장하지 않음
  saveUninitialized: false,      // 로그인하기 전에는 세션을 만들지 않음
  cookie: {
    httpOnly: true,              // 자바스크립트로 쿠키를 읽을 수 없게 (XSS 방어)
    maxAge: 1000 * 60 * 60       // 1시간 뒤 만료
  }
}));

// 본문 요청 파싱
app.use(express.json());
  • cors()는 모든 주소를 허용하지만, 쿠키를 주고받을 때는 origin에 React 주소를 정확히 적고 credentials: true를 켜야 합니다.
  • secret — 세션 ID 쿠키에 서명해 위조를 막는 비밀 키입니다. 배포할 때는 환경변수로 넣습니다.
  • httpOnly: true — 자바스크립트(document.cookie)로 쿠키를 읽을 수 없어, 악성 스크립트가 세션 ID를 훔쳐 가기 어렵습니다.
  • 세션은 기본적으로 서버 메모리에 저장됩니다. 서버를 다시 시작하면(nodemon 포함) 모든 세션이 사라져 다시 로그인해야 합니다.
💡 예제 — ② 로그인 확인 · 관리자 확인 미들웨어
server/index.js (express.json() 아래) 
// 로그인했는지 확인하는 미들웨어
const requireLogin = (req, res, next) => {
  if (!req.session.user) {
    return res.status(401).send("로그인이 필요합니다.");
  }
  next();   // 다음 단계(라우터)로 넘어감
};

// 관리자인지 확인하는 미들웨어
const requireAdmin = (req, res, next) => {
  if (req.session.user?.role !== "admin") {
    return res.status(403).send("관리자만 사용할 수 있습니다.");
  }
  next();
};
  • req.session — express-session이 요청마다 쿠키의 세션 ID로 찾아서 넣어 주는 객체입니다. 로그인할 때 req.session.user에 회원 정보를 넣어 둡니다.
  • 401(Unauthorized) — 로그인하지 않음, 403(Forbidden) — 로그인했지만 권한 없음.
  • next()를 부르면 다음 미들웨어나 라우터 함수로 넘어가고, 부르지 않고 응답을 보내면 거기서 끝납니다.
💡 예제 — ③ 로그인 · 로그인 확인 · 로그아웃 API
server/index.js (회원 API의 로그인 바꾸기) 
// 로그인: 비밀번호가 맞으면 세션에 회원 정보를 저장합니다.
app.post("/api/users/login", async (req, res) => {
  const { username, password } = req.body;
  const sql = "SELECT * FROM users WHERE username = $1";
  try {
    const result = await db.query(sql, [username]);
    const user = result.rows[0];
    if (!user || !(await bcrypt.compare(password, user.password))) {
      return res.status(401).send("아이디 또는 비밀번호가 올바르지 않습니다.");
    }
    const { password: _, ...userInfo } = user;
    req.session.user = userInfo;   // 세션에 로그인 정보 저장
    res.json({ message: "로그인 성공", user: userInfo });
  } catch (err) {
    console.log("회원 로그인 오류!", err);
    res.status(500).send("로그인 중 오류가 발생했습니다.");
  }
});

// 로그인 확인: 새로고침해도 세션에 남아 있는 회원 정보를 돌려줍니다.
app.get("/api/users/me", requireLogin, (req, res) => {
  res.json(req.session.user);
});

// 로그아웃: 서버의 세션을 지우고 쿠키도 지웁니다.
app.post("/api/users/logout", (req, res) => {
  req.session.destroy(() => {
    res.clearCookie("connect.sid");
    res.send("로그아웃 완료");
  });
});
  • 로그인에 성공하면 req.session.user = userInfo로 세션에 저장합니다. 이때 express-session이 응답에 Set-Cookie: connect.sid=…를 붙입니다.
  • GET /api/users/me — React가 새로고침 직후 "나 로그인되어 있나?"를 물어보는 API입니다. 세션이 있으면 회원 정보를, 없으면 requireLogin이 401을 돌려줍니다.
  • req.session.destroy()로 서버의 세션을 지우고, res.clearCookie("connect.sid")로 브라우저 쿠키도 지웁니다.

// 회원 정보 수정 (이름 · 이메일)
app.put("/api/users/:id", requireLogin, async (req, res) => {
  // 세션의 회원 번호와 주소의 번호가 다르면 막음 (본인만 수정)
  if (req.session.user.id !== Number(req.params.id)) {
    return res.status(403).send("본인 정보만 수정할 수 있습니다.");
  }
  const uid = req.params.id;
  const { name, email } = req.body;
  // RETURNING: 바꾼 뒤의 회원 정보를 바로 돌려받습니다. (password는 빼고)
  const sql = "UPDATE users SET name = $1, email = $2 WHERE id = $3 "
        + "RETURNING id, username, name, email, role, created_at";
  try {
    const result = await db.query(sql, [name, email, uid]);
    if (result.rows.length === 0) {
      return res.status(404).send("회원을 찾을 수 없습니다.");
    }
    req.session.user = result.rows[0];   // 세션의 회원 정보도 새 값으로
    res.json(result.rows[0]);
  } catch (err) {
    // 23505: UNIQUE 위반 (다른 회원이 쓰는 이메일)
    if (err.code === "23505") {
      return res.status(409).send("이미 사용 중인 이메일입니다.");
    }
    console.log("회원 수정 오류!", err);
    res.status(500).send("회원 정보 수정 중 오류가 발생했습니다.");
  }
});
  • app.post(경로, 미들웨어, 함수)처럼 경로와 함수 사이에 미들웨어를 넣으면 그 API에만 적용됩니다. 상품 목록 · 상세 조회(GET)는 누구나 볼 수 있게 그대로 둡니다.
  • 회원 정보 수정은 본인만: 세션의 회원 번호와 주소의 :id가 같은지 확인합니다. 주소의 값은 문자열이라 Number()로 바꿔 비교합니다.
  • 수정에 성공하면 req.session.user도 새 값으로 바꿔, 새로고침해도 바뀐 이름이 나오게 합니다.
💡 테스트 (Postman)
  • 로그인하지 않고 POST /api/products → 403 관리자만 사용할 수 있습니다.
  • POST /api/users/login(관리자) → 응답의 Cookies 탭에 connect.sid가 생깁니다. Postman은 받은 쿠키를 다음 요청에 자동으로 붙여 줍니다.
  • 다시 POST /api/products → 200 상품 등록 완료!!
  • POST /api/users/logout 후 GET /api/users/me → 401 로그인이 필요합니다.

💡 예제 — ⑦ Context와 Provider: 새로고침해도 로그인 유지
src/context/UserContext.ts 
// 회원 컨텍스트 타입 정의
// 서버에 물어봐야 하므로 signup · login은 Promise를 돌려줍니다.
interface UserContextType{
    users: User[];  // 회원목록
    currentUser: User | null;  // 로그인한 회원 (로그아웃 상태면 null)
    isAuthLoading: boolean;  // 로그인 상태 확인 중 여부
    signup: (newUser: NewUser) => Promise<void>  // 회원가입
    login: (loginForm: LoginForm) => Promise<boolean>  // 로그인 (성공 여부 반환)
    logout: () => Promise<void>  // 로그아웃 (서버에 요청)
    updateUser: (form: UserUpdateForm) => Promise<void>  // 회원 정보 수정
}

import { createUser, getMe, getUsers, modifyUser, requestLogin, requestLogout } from "../api/users";

3 JWT 토큰 인증 (jsonwebtoken)

🎯 학습목표
  • JWT의 구조(헤더 · 내용 · 서명)와 동작 원리를 설명할 수 있다.
  • jwt.sign()으로 토큰을 만들고 jwt.verify()로 확인할 수 있다.
  • axios 인터셉터로 요청마다 토큰을 헤더에 붙일 수 있다.

📖 JWT 인증 흐름과 구조

[로그인] 브라우저 ── POST /api/users/login (아이디 · 비밀번호) ──▶ 서버 서버: 비밀번호 확인 → jwt.sign({ id, username, role }, 비밀키) → 토큰 ◀── { user, token } ── 브라우저: localStorage에 token 저장 [다음 요청부터] 브라우저 ── 요청 + Authorization: Bearer 토큰 (인터셉터가 붙임) ──▶ 서버 서버: jwt.verify(토큰, 비밀키) → 서명 · 만료 확인 → 누구인지 앎 (DB · 메모리 조회 없음)
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9 . eyJpZCI6NCwidXNlcm5hbWUiOiJ1c2VyMSIs... . 서명 ──────────── 헤더 ──────────── ──────────── 내용(payload) ──────────── ─ 서명 ─ { "alg": "HS256" } { "id": 4, "username": "user1", 비밀키로 만든 값 "role": "user", "iat": …, "exp": … } (위조 확인용)
  • 토큰은 점(.)으로 나뉜 세 부분입니다. 헤더와 내용은 암호화가 아니라 인코딩(Base64)이라 누구나 읽을 수 있습니다. 그래서 비밀번호 같은 비밀 값은 넣지 않습니다.
  • 서명은 서버의 비밀키로 만든 값입니다. 누가 내용의 role을 admin으로 바꾸면 서명이 맞지 않아 jwt.verify()에서 거부됩니다.
  • exp(만료 시간)가 지나면 토큰은 쓸 수 없습니다. 서버가 토큰을 따로 저장하지 않으므로 로그아웃은 브라우저에서 토큰을 지우는 것입니다.

💡 예제 — ② 토큰 확인 · 관리자 확인 미들웨어
server/index.js (express.json() 아래) 
// 토큰 확인 미들웨어: 요청 헤더 Authorization: Bearer <토큰> 을 검사합니다.
const requireLogin = (req, res, next) => {
  const header = req.headers.authorization;   // "Bearer eyJhbGciOi..."
  const token = header?.startsWith("Bearer ") ? header.slice(7) : null;
  if (!token) {
    return res.status(401).send("로그인이 필요합니다.");
  }
  try {
    // 서명과 만료 시간을 확인하고, 토큰에 담은 회원 정보를 꺼냅니다.
    req.user = jwt.verify(token, JWT_SECRET);
    next();
  } catch {
    return res.status(401).send("토큰이 만료되었거나 올바르지 않습니다.");
  }
};

// 관리자 확인 미들웨어: requireLogin 다음에 씁니다.
const requireAdmin = (req, res, next) => {
  if (req.user?.role !== "admin") {
    return res.status(403).send("관리자만 사용할 수 있습니다.");
  }
  next();
};
  • 토큰은 요청 헤더 Authorization: Bearer 토큰으로 옵니다. 앞의 "Bearer "(7글자)를 잘라 내고 토큰만 꺼냅니다.
  • jwt.verify()는 서명이 틀리거나 만료되었으면 오류를 던집니다. 그래서 try / catch로 감싸 401을 돌려줍니다.
  • 성공하면 토큰 안의 회원 정보를 req.user에 넣어, 다음 미들웨어와 라우터에서 씁니다.
  • requireAdmin은 req.user가 필요하므로 항상 requireLogin 다음에 씁니다.
💡 예제 — ③ 로그인: 토큰 발급 · 로그인 확인 API
server/index.js (회원 API의 로그인 바꾸기) 
// 로그인: 비밀번호가 맞으면 토큰을 만들어 돌려줍니다.
app.post("/api/users/login", async (req, res) => {
  const { username, password } = req.body;
  const sql = "SELECT * FROM users WHERE username = $1";
  try {
    const result = await db.query(sql, [username]);
    const user = result.rows[0];
    if (!user || !(await bcrypt.compare(password, user.password))) {
      return res.status(401).send("아이디 또는 비밀번호가 올바르지 않습니다.");
    }
    const { password: _, ...userInfo } = user;
    // 토큰에는 꼭 필요한 값만 담습니다. (비밀번호 X)
    const token = jwt.sign(
      { id: user.id, username: user.username, role: user.role },
      JWT_SECRET,
      { expiresIn: "1h" }   // 1시간 뒤 만료
    );
    res.json({ message: "로그인 성공", user: userInfo, token });
  } catch (err) {
    console.log("회원 로그인 오류!", err);
    res.status(500).send("로그인 중 오류가 발생했습니다.");
  }
});

// 로그인 확인: 토큰의 회원 번호로 DB에서 최신 회원 정보를 돌려줍니다.
app.get("/api/users/me", requireLogin, async (req, res) => {
  const sql = "SELECT id, username, name, email, role, created_at FROM users WHERE id = $1";
  try {
    const result = await db.query(sql, [req.user.id]);
    if (result.rows.length === 0) {
      return res.status(404).send("회원을 찾을 수 없습니다.");
    }
    res.json(result.rows[0]);
  } catch (err) {
    console.log("회원 조회 오류!", err);
    res.status(500).send("회원 조회 중 오류가 발생했습니다.");
  }
});
  • jwt.sign(내용, 비밀키, {{ expiresIn: "1h" }}) — 1시간 동안 쓸 수 있는 토큰을 만듭니다. 내용에는 회원 번호 · 아이디 · 권한만 넣습니다.
  • 응답에 token을 함께 보내면 React가 저장해 두었다가 요청마다 붙입니다.
  • /api/users/me는 토큰의 id로 DB에서 최신 회원 정보를 찾아 돌려줍니다. 이름을 바꾼 뒤에도 바른 값이 나옵니다.
  • 로그아웃 API는 만들지 않습니다. 서버에 지울 것이 없기 때문입니다.

💡 주의 — localStorage와 XSS localStorage는 자바스크립트로 읽을 수 있어, 사이트에 악성 스크립트가 들어오면(XSS) 토큰을 훔쳐 갈 수 있습니다. 세션의 httpOnly 쿠키는 자바스크립트로 읽을 수 없어 이 점에서 더 안전합니다. 토큰을 쓸 때는 만료 시간을 짧게 두고, 사용자 입력을 그대로 HTML로 넣지 않습니다.

📖 정리

  1. JWT는 회원 정보를 토큰 안에 담고, 서버는 비밀키로 서명과 만료만 확인합니다.
  2. 토큰 내용은 누구나 읽을 수 있으므로 비밀 값은 넣지 않습니다.
  3. React는 토큰을 localStorage에 두고, axios 인터셉터로 Authorization: Bearer 토큰을 붙입니다.
  4. 로그아웃은 토큰 삭제이고, 토큰은 만료 시간이 지나면 쓸 수 없습니다.
