1 Thymeleaf 화면 구성

🎯 학습목표
  • @Controller에서 Model에 데이터를 담아 템플릿으로 넘길 수 있다.
  • th:text · th:each · th:if · @{...} 문법을 사용할 수 있다.

📖 자주 쓰는 Thymeleaf 문법 (example.html로 연습)

문법의미예
${...}모델 값 꺼내기th:text="${article.title}"
*{...}th:object로 선택한 객체의 필드th:text="*{name}"
@{...}URL 만들기@{/articles/{id}(id=${item.id})}
th:each반복th:each="item : ${articles}"
th:if조건부 출력th:if="${article.id} == null"
|...|문자열 합치기th:text="|Posted on ${...}|"
#temporals날짜 포맷${#temporals.format(today, 'yyyy-MM-dd')}

▶ 연습 — ExampleController + example.html

💡 controller/ExampleController.java
@Controller
public class ExampleController {

    @GetMapping("/thymeleaf/example")
    public String thymeleafExample(Model model){
        Person person = new Person();
        person.setId(1L);
        person.setName("우영우");
        person.setAge(31);
        person.setHobbies(List.of("독서", "음악감상"));

        model.addAttribute("person", person);
        model.addAttribute("today", LocalDate.now());

        return "example";
    }

    @Setter
    @Getter
    static class Person {
        private Long id;
        private String name;
        private int age;
        private List<String> hobbies;
    }
}

연습용 Person 객체와 오늘 날짜를 Model에 담아 templates/example.html로 넘긴다.

코드확인할 문법
${#temporals.format(today, 'yyyy-MM-dd')}날짜 객체 포맷
th:object="${person}" + *{name}객체를 한 번 선택하면 *{필드}로 짧게 쓴다
|이름: *{name}|문자열과 값 합치기
th:each="hobby : *{hobbies}"리스트 반복
th:if="${hobby == '독서'}"조건이 참일 때만 출력
@{/articles/{id}(id=${person.id})}경로 변수 URL → /articles/1
⚠️ 자주 하는 실수
  • th:each는 반복할 태그에 붙인다. <ul th:each>로 쓰면 목록(ul) 자체가 취미 수만큼 생긴다 → <li th:each>
  • <ul> 바로 안에는 <li>만 둘 수 있다. <span>은 <li> 안에 넣는다.
  • "글 보기" 화면은 /articles/1이다. /api/articles/1은 JSON 응답이라 화면 대신 데이터가 보인다.
  • 컨트롤러 안의 Person은 static 중첩 클래스로 만든다 (바깥 객체 없이 독립적으로 쓰는 데이터 클래스).
💡 dto/ArticleListViewResponse.java — 목록 화면용 DTO
@Getter
public class ArticleListViewResponse {
    private final Long id;
    private final String title;
    private final String content;
    private final String imageUrl;

    public ArticleListViewResponse(Article article) {
        this.id = article.getId();
        this.title = article.getTitle();
        this.content = article.getContent();
        this.imageUrl = article.getImageUrl();
    }
}
💡 API용 ArticleResponse와 무엇이 다를까? — 화면에서는 글 제목을 누르면 /articles/{id} 상세 페이지로 이동해야 하므로 id가 필요하다. 필드를 final로 두어 만든 뒤에는 바뀌지 않는 읽기 전용 객체로 쓴다 (setter 없음, @Getter만).
💡 dto/ArticleViewResponse.java — 상세 · 등록/수정 화면용 DTO
@NoArgsConstructor   // 새 글 화면: new ArticleViewResponse() → 모든 값 null
@Getter
public class ArticleViewResponse {
    private Long id;
    private String title;
    private String content;
    private String imageUrl;
    private LocalDateTime createdAt;

    public ArticleViewResponse(Article article) {
        this.id = article.getId();
        this.title = article.getTitle();
        this.content = article.getContent();
        this.imageUrl = article.getImageUrl();
        this.createdAt = article.getCreatedAt();
    }
}
생성자쓰는 곳결과
new ArticleViewResponse(article)상세 화면, 수정 화면 (/new-article?id=1)DB 글 내용이 채워짐 → 수정 버튼
new ArticleViewResponse()새 글 화면 (/new-article)id가 null → 등록 버튼
💡 왜 기본 생성자? — 빈 화면을 위해 Article.builder().build()처럼 DB 엔티티를 일부러 만들 필요가 없다. 화면용 DTO만 비워서 넘기면 된다. final이 아닌 필드라 기본 생성자를 둘 수 있다.
💡 controller/BlogViewController.java
@RequiredArgsConstructor
@Controller   // 템플릿 이름(String)을 반환
public class BlogViewController {
    private final BlogService blogService;

    @GetMapping("/articles")
    public String getArticles(Model model) {
        List<ArticleListViewResponse> articles = blogService.findAll().stream()
                .map(ArticleListViewResponse::new)
                .toList();
        model.addAttribute("articles", articles);
        return "articleList";                    // templates/articleList.html
    }

    @GetMapping("/articles/{id}")
    public String getArticle(@PathVariable Long id, Model model) {
        model.addAttribute("article", new ArticleViewResponse(blogService.findById(id)));
        return "article";
    }

    // id가 없으면 새 글, 있으면 수정 화면
    @GetMapping("/new-article")
    public String newArticle(@RequestParam(required = false) Long id, Model model) {
        if (id == null) {
            model.addAttribute("article", new ArticleViewResponse());
        } else {
            model.addAttribute("article", new ArticleViewResponse(blogService.findById(id)));
        }
        return "newArticle";
    }
}

2 프론트엔드 JS — fetch로 API 호출

🎯 학습목표
  • fetch()로 REST API를 호출하고 결과에 따라 페이지를 이동시킬 수 있다.

📖 개념 및 설명

static/js/article.js 한 파일이 모든 화면에 포함된다. 버튼이 있는 화면에서만 이벤트를 등록하도록 if (button)으로 감싼다.

버튼 클릭→fetch(URL, {method, body})→API 응답→alert + location.replace()
💡 static/js/article.js — 등록 · 수정 · 삭제
// 응답이 실패(4xx, 5xx)면 오류를 던진다 → catch에서 알림
function checkResponse(response) {
    if (!response.ok) {
        throw new Error(`요청 실패 (${response.status})`);
    }
    return response;
}

// 제목·내용이 비어 있으면 서버로 보내지 않는다 (DB에서 NOT NULL)
function readForm() {
    const title = document.getElementById('title').value.trim();
    const content = document.getElementById('content').value.trim();
    if (!title || !content) {
        alert('제목과 내용을 입력하세요.');
        return null;
    }
    return {
        title: title,
        content: content,
        imageUrl: document.getElementById('image-url')?.value || null
    };
}

const deleteButton = document.getElementById('delete-btn');

            location.replace(`/articles/${id}`);
        })
        .catch(error => alert('수정 실패: ' + error.message));

}

코드역할
checkResponse()fetch()는 서버가 400·500을 돌려줘도 실패로 보지 않는다. response.ok를 직접 확인해 실패면 오류를 던진다.
.catch(error => alert(...))실패하면 "등록 완료" 대신 "등록 실패 (500)"처럼 알린다.
readForm()제목·내용을 읽어 공백을 지우고(trim()), 비어 있으면 서버로 보내지 않는다. 등록·수정이 함께 쓴다.
?.value || nullimage-url 칸이 없거나 비어 있으면 null을 보낸다.
imageUrl까지 PUT수정할 때 imageUrl을 빠뜨리면 update()가 이미지 경로를 null로 덮어쓴다.

3 이미지 업로드

🎯 학습목표
  • MultipartFile로 파일을 받아 서버에 저장하고 URL로 제공할 수 있다.
  • 저장 방식을 인터페이스로 추상화하는 이유를 이해한다.

📖 업로드 흐름

파일 선택→POST /api/upload (FormData)→uploads/UUID.jpg 저장→{imageUrl} 응답→hidden input 저장 + 미리보기→글 등록 시 함께 전송
  • 파일명은 UUID로 바꿔 저장한다 → 이름 충돌·한글 파일명 문제 방지
  • FileStorageService 인터페이스 덕분에 나중에 S3 저장소로 바꿀 때 컨트롤러는 그대로 둔다.
💡 service/FileStorageService.java · LocalFileStorageService.java
public interface FileStorageService {
    UploadResponse store(byte[] bytes, String filename);
}

@Service
public class LocalFileStorageService implements FileStorageService {
    private final Path uploadDir;

    // app.upload-dir 설정이 없으면 기본값 "uploads"
    public LocalFileStorageService(@Value("${app.upload-dir:uploads}") String uploadDir) {
        this.uploadDir = Paths.get(uploadDir).toAbsolutePath().normalize();
    }

    @Override
    public UploadResponse store(byte[] bytes, String filename) {
        try {
            Files.createDirectories(uploadDir);
            String ext = filename.contains(".")
                    ? filename.substring(filename.lastIndexOf('.'))
                    : ".png";
            String saved = UUID.randomUUID() + ext;          // 고유한 파일명
            Files.write(uploadDir.resolve(saved), bytes);
            return new UploadResponse("/uploads/" + saved);
        } catch (IOException e) {
            throw new RuntimeException("파일 저장에 실패했습니다.", e);
        }
    }
}
⚠️ @Service를 빠뜨리면 — 앱이 시작되지 않고 아래 오류가 난다. 인터페이스(FileStorageService)만 있고 구현 클래스가 빈으로 등록되지 않아 UploadController에 넣어 줄 객체가 없기 때문이다. 구현 클래스에 @Service를 붙인다.

💡 controller/UploadController.java · config/WebMvcConfig.java
@RestController
public class UploadController {
    private final FileStorageService fileStorageService;

    public UploadController(FileStorageService fileStorageService) {
        this.fileStorageService = fileStorageService;
    }

    @PostMapping("/api/upload")
    public ResponseEntity<UploadResponse> uploadFile(@RequestParam("file") MultipartFile file)
            throws IOException {
        return ResponseEntity.status(HttpStatus.CREATED)
                .body(fileStorageService.store(file.getBytes(), file.getOriginalFilename()));
    }
}

// /uploads/** 요청 → 프로젝트의 uploads/ 폴더 파일을 그대로 제공
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {
    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        registry.addResourceHandler("/uploads/**")
                .addResourceLocations("file:uploads/");
    }
}
▶ Postman으로 업로드 테스트 — POST /api/upload
  1. 메서드 POST, URL http://localhost:8080/api/upload
  2. Body → form-data → Key에 file 입력, 오른쪽 종류를 File로 바꾸고 Value에서 이미지 선택
  3. Send → 201 Created와 {"imageUrl": "/uploads/UUID.jpg"}가 오면 성공
  4. 브라우저에서 http://localhost:8080/uploads/UUID.jpg를 열어 이미지가 보이는지 확인 (WebMvcConfig가 연결)

저장 위치 확인 — IntelliJ 프로젝트 창에 uploads 폴더가 생기고, 응답의 imageUrl과 같은 이름(UUID)의 파일이 들어 있다. 원래 파일 이름 대신 UUID를 쓰는 이유는 같은 이름의 파일이 서로 덮어쓰지 않게 하기 위해서다.

글에 이미지 붙이기 — 받은 imageUrl을 글 등록 요청(POST /api/articles, Body raw · JSON)에 넣는다. 등록 화면에서는 article.js가 이 두 요청을 차례로 보낸다.

⚠️ 자주 나는 오류
  • 415 Unsupported Media Type (multipart/form-data ... is not supported): 파일을 /api/articles로 보냈다. 파일은 /api/upload로 보낸다.
  • 400 Bad Request (Required part 'file' is not present): form-data의 Key가 비었거나 file이 아니다.
  • Value 옆 ⚠️ 표시: Postman이 파일 위치를 못 찾는다. Select Files로 다시 고른다.

📖 동작 원리

모달에서 질문 입력→POST /api/ai-suggestions→템플릿에 제목·내용·질문·{format} 채움→ChatClient → Gemini→JSON → WritingSuggestionResponse→제안 클릭 시 본문에 추가
  • {format} 자리에는 BeanOutputConverter.getFormat()이 만든 "이 JSON 스키마로 답하라"는 지시문이 들어간다.
  • 그래서 LLM의 답을 {"suggestions": ["...", "...", "..."]} 형태로 받아 record로 바로 변환할 수 있다.
💡 resources/prompts/writing-assistant.st
당신은 블로그 글쓰기를 도와주는 전문 작가입니다.

제목: {title}
현재 작성된 내용: {content}
질문: {question}

위 질문에 대해 3개의 구체적이고 실용적인 제안을 해 주세요.

{format}
💡 dto (record) · service/WritingAssistantService.java
public record WritingSuggestionRequest(String title, String content, String question) {
    public Map<String, Object> toMap(String format) {
        return Map.of("title", title, "content", content,
                      "question", question, "format", format);
    }
}

public record WritingSuggestionResponse(List<String> suggestions) {}

@Service
public class WritingAssistantService {
    private final ChatClient chatClient;
    private final PromptTemplate template;

    // LLM의 JSON 응답 → WritingSuggestionResponse 변환기
    private final BeanOutputConverter<WritingSuggestionResponse> outputConverter =
            new BeanOutputConverter<>(WritingSuggestionResponse.class);

    public WritingAssistantService(
            ChatClient.Builder chatClientBuilder,
            @Value("classpath:prompts/writing-assistant.st") Resource promptResource) {
        this.chatClient = chatClientBuilder.build();
        this.template = new PromptTemplate(promptResource);
    }

    public WritingSuggestionResponse getWritingAssist(WritingSuggestionRequest request) {
        // 1) 템플릿에 값 채워 최종 프롬프트 생성
        String prompt = template.create(request.toMap(outputConverter.getFormat())).getContents();
        // 2) LLM 호출
        String response = chatClient.prompt().user(prompt).call().content();
        // 3) JSON → 객체
        return outputConverter.convert(response);
    }
}
